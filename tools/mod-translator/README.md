# Собственный ModSDK source-subset 0.1

Это отдельный исходный API серверных модов MCSA для **26.3 / protocol 777**.
Он использует существующую песочницу `mcsa:api@0.1.0`, без новых прав и без
отдельной JVM. Это **не загрузчик и не переводчик произвольных Fabric/Forge JAR**.
Проверены только самостоятельно написанные fixture. Совместимость с модами
1.21.1, клиентскими модами, Mixin, новыми блоками/предметами не заявляется.

CLI принимает ровно два файла: собственный `mod.toml` и собственный `.java`.
Не передавайте сторонние исходники или JAR: их чтение/распаковка не требуется.
Для переноса существующего мода разработчик должен сам переписать поддерживаемую
серверную логику на этот API. Неподдерживаемые imports/методы/выражения, лишние
классы, файлы, assets и mixin-конфиги вызывают полный отказ с русской причиной.
Никакое неизвестное поведение не вырезается ради получения компонента.

## Пример и команды

В `mod.toml` поле `api = "mcsa-mod-source-0.1"` задаёт профиль исходника,
`sdk_abi = "mcsa:api@0.1.0"` — ABI компонента, а `minecraft = "26.3"` и
`protocol = 777` — целевую версию Java Edition и протокола. Переводчик
проверяет каждое значение. Для прежнего манифеста без `sdk_abi` с этим
профилем и целью действует ABI `mcsa:api@0.1.0`. Неизвестное значение
`sdk_abi` вызывает отказ с кодом `sdk-abi`.

```sh
python3 tools/mod-translator/translate.py tools/mod-api/fixtures/welcome --check-only --report /tmp/mod-check.json
python3 tools/mod-translator/translate.py tools/mod-api/fixtures/welcome --emit-c /tmp/own-mod.c
# Тяжёлая сборка выполняется только на GitHub, не на ПК владелицы:
python3 tools/mod-translator/build_fixtures.py
```

`--check-only` проверяет весь source-subset и EOF, не проверяет компиляцию WASM.
`--emit-c` сохраняет код только после полного разбора. Обычный запуск выполняет
`wit-bindgen c --world plugin`, WASI C-компиляцию и `wasm-tools validate`, затем
атомарно создаёт `plugins/<name>/{plugin.toml,plugin.wasm,conversion.json,data/}`.
Существующая папка не перезаписывается. `conversion.json` содержит SHA исходника
и WASM и число обработчиков. В `conversion.json` и в отчёте об успешной
проверке указаны профиль исходника, целевая версия с протоколом и ABI компонента.
Исполнение в хозяине проверяет отдельный runtime-тест, описанный ниже.

Инструменты уже закреплены существующей цепочкой:
`wit-bindgen 0.63.0`, `wasi-sdk 34`, `wasm-tools 1.262.0` в
`tools/plugin-translator/.toolchain/`; можно указать `--toolchain DIR`.
Переводчик не скачивает инструменты, не запускает Java/TeaVM и не исполняет
исходник на JVM. Байты новых бинарных зависимостей не добавлены.

## Точный поддержанный язык

Интерфейсы для IDE/javac написаны нами в `tools/mod-api/src/ru/mcsa/modapi/`.
Это контракт, не альтернативная JVM-реализация.

* Два явных imports `ru.mcsa.modapi.Mod` и `ru.mcsa.modapi.Context`.
* Один `public final class Имя implements Mod`, без package, полей, наследования,
  дополнительных методов или аннотаций. Имя совпадает с `.java`.
* Единственный `public void initialize(Context ctx)`. В нём только регистрации
  `ctx.onStart(() -> {...})`, `onStop`, `onJoin(player -> {...})`, `onQuit`,
  `every(период, () -> {...})`; не более 64 регистраций.
* В обработчиках только `ctx.log(строка)`, `ctx.broadcast(строка)` и
  `ctx.message(player, строка)` (последнее только join/quit).
* Строка: литералы с `\"`, `\\`, `\n`, `\r`, `\t` и их конкатенация через `+`;
  внутри player-callback также `player.name()` и `player.uuid()`. До 32 частей,
  4096 UTF-8 байт на литерал, 64 действий на callback, 64 КиБ на исходник.
* Комментарии `//`, `/* */` разрешены, Java Unicode escapes запрещены целиком,
  включая комментарии. Числа только положительные десятичные без ведущих нулей.

Полный лексер и последовательный разбор не пропускают незнакомые токены.
Объекты, условия, циклы, состояние, исключения, произвольные Java-вызовы,
рефлексия, потоки, загрузчики, native, NMS, Fabric/Forge API не поддержаны.
Профиль специально мал: это не второй общий компилятор Java.

## События и ограничения хозяина

`initialize` — статическая регистрация, выполняемая переводчиком, без произвольных
эффектов. При загрузке регистрируются все periodic-задачи, затем идут onStart.
Обработчики одного события вызываются в порядке регистрации. Каждому every
принадлежит свой task-id и handle; период 1..2400000. Первый вызов через period
тактов, последующие по существующему scheduler хозяина; при скачке номера такта
нет компенсации пропущенных вызовов. При выгрузке задачи отменяются перед onStop,
после выгрузки Store и всё состояние уничтожаются. Новая загрузка начинает заново.
Разные моды получают разные Store, task handles и память.

Join/quit — существующие серверные события; это не полная событийная модель
Fabric/Forge. `onStart` здесь значит загрузку мода, не окончание генерации мира.
Снимок player актуален только на время callback. Необъявленные события проходят
как обычно (chat pass, block/command allow); для них нет заявленных обработчиков.

`broadcast` наследует существующее правило хозяина: управляющие знаки и §
удаляются, текст обрезается до 256 символов; пустой текст не публикуется.
`message` работает только для присутствующего игрока, сохраняет переносы строк,
прочие управляющие знаки удаляет. На quit игрок может уже отсутствовать, поэтому
доставка message в onQuit не гарантируется; fixture использует broadcast.
`log` пишет INFO. Это поведение собственного API, а не эмуляция чужого loader.
Работают существующие лимиты Wasmtime: память/топливо/эпохи, без privileged.

## Проверки

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tools/mod-translator/test_compiler.py
# CI, после установки закреплённых инструментов и сборки двух fixture:
python3 tools/mod-translator/build_fixtures.py
cargo test --release plugins::tests::own_mod_source_tests::translated_own_mod_source_lifecycle_events_and_isolation -- --ignored --exact --test-threads=1
```

Для последней команды основной помощник подключает
`include!(concat!(env!("CARGO_MANIFEST_DIR"), "/tools/mod-translator/host_tests.rs"));`
в `src/plugins/tests.rs`. Это только тестовый hook; production host, Cargo и WIT
не меняются. Тест не пропускается при отсутствии WASM: проверяет реальные
load/start, два join-callback с точными NBT и порядком, quit, every 2/3,
ранний такт, повтор, unload/stop, чужой task handle, повторную загрузку,
второй Store и отсутствие callbacks после unload. Сетевой Minecraft-клиент,
реальные Fabric/Forge-моды и Android этим тестом не проверяются.


## Типизированное событие чата (добавление 19 ноября)

`ctx.onChat(chat -> { ... });` получает собственный `ChatEvent`: `message()`,
`playerName()` и `playerUuid()` возвращают исходный текст и снимок отправителя
из WIT-вызова. Объект существует только во время callback. `chat.cancel();`
необратимо отменяет доставку этого сообщения. Все обработчики текущего мода
всё равно выполняются в порядке регистрации; каждый получает тот же текст.
При следующем сообщении флаг отмены начинается заново. Без отмены возвращается
Pass. Между разными модами действует текущий порядок хозяина; после Cancel
хозяин может не вызывать следующие моды — общей транзакции здесь нет.

В onChat доступны log/broadcast со строковыми полями события; личное сообщение
через этот объект, изменение текста, снятие отмены, сторонние getters и сохранение
события не поддержаны и приводят к полному отказу перевода. Broadcast по-прежнему
применяет собственные ограничения хозяина; он не является исходной доставкой чата.
Публичный SDK получил ChatEvent и Context.onChat; ABI WIT не менялся, прежние
шестипольные манифесты и optional sdk_abi продолжают приниматься.

Собственная fixture `tools/mod-api/fixtures/chat` намеренно отменяет каждое
сообщение и публикует две диагностические строки для проверки порядка.
На GitHub: `python3 -B tools/mod-translator/build_fixtures.py --chat`, затем
`cargo test --locked --release --bin mcsheriffanya plugins::tests::own_mod_source_tests::translated_own_mod_chat_is_typed_ordered_and_cancelled -- --ignored --exact --test-threads=1`.
Этот новый Host-тест подготовлен, но ещё НЕ выполнен. Локальные Python-проверки
не доказывают новую WASM-сборку или игровую доставку. Это небольшой собственный
API-срез, не совместимость Fabric/Forge и не полноценный API будущих модов.
