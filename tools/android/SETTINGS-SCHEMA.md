# Новые поля Android с обновлением ядра

После одного начального обновления APK приложение читает необязательное `settings`
из подписанного описания **выбранного** ядра. Без него остаются прежние 28 полей.
Неверное дополнение целиком отклоняется; приложение показывает причину общими словами.
Встроенное ядро не получает новые поля из описания другого слота.

`settings-schema.json` описывает четыре параметра нового кода: `enable-nether`,
`enable-end`, `experimental-parallel-mobs`, `mob-tick-threads`. Все находятся в
`config/mcsa.properties`. Начальные значения записываются строками, включая числа
и переключатели. Это описание нельзя публиковать для старого ядра.

Перед подписью необходимо проверить поддержку всех четырёх параметров в **точном**
исходном commit из native pin и получить успешные проверки этого native build.
Проверка одного лишь имени или версии недостаточна. Источник native receipt,
`pin.head`, `payload.source` и `--settings-source` должны совпадать. Последний аргумент
является явной привязкой решения издателя к проверенному исходному commit;
скрипт не доказывает игровую поддержку параметров анализом исходников.

Дополнить обычный вызов `sign-core-update.py` аргументами:

```
--settings-schema tools/android/settings-schema.json --settings-source FULL_VERIFIED_CORE_COMMIT_SHA
```

Без `--settings-schema` поле `settings` не добавляется: прежняя публикация остаётся
совместимой. Проверка описания выполняется до обращения к локальному OpenSSL.
Описание попадает внутрь подписываемых байтов, а не рядом с подписью. Скрипт не
публикует результат в сеть. Приватный ключ остаётся только на этом компьютере.

Лёгкие проверки без подписи и без доступа к ключу:

```
python3 -B -m unittest discover -s tools/android -p test_settings_schema.py
```
