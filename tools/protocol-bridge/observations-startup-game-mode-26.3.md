# Начальный режим игры — Java26.3 / протокол777

Оригинальный сервер запускался как непрозрачный JAR с SHA1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`. Исходники/реализации протокола
не читались, JAR не распаковывался. Собственный клиент использует закреплённую
разрешённую JSON-схему777, SHA256
`13a10695aa1ed3604ed674ce8fdc8a759f48118714eab98644e685a3d1960727`.

`testdata/startup-game-mode-original-777.json` хранит наблюдаемые Login/Abilities
своих игроков и SHA двух исходных записей. Только метаданные входа, без чанков
и выгрузок реестров. Проба запускает обычный серверный entrypoint, без тестового
конструктора и без команд изменения режима перед первым входом.

| `gamemode` | Новый игрок | Флаги Abilities |
|---|---:|---:|
| `survival`, `0` | 0 | 0 |
| `creative`, `1` | 1 | 13 |
| `adventure`, `2` | 2 | 0 |
| `spectator`, `3` | 3 | 7 |
| отсутствует, пусто, `Creative`, `invalid`, `4`, `-1` | 0 | 0 |

Во всех этих входах скорости Abilities одинаковы: float32 `0.05` и `0.1`.
После смены режима своего игрока на adventure и сохранения сервер перезапущен
с `gamemode=creative`: прежний игрок остался adventure, новый получил creative.
После `/defaultgamemode spectator` ещё один новый игрок получил spectator.
Итого14 настроек и17 наблюдений входа/способностей. Старая обычная сборка нашего
ядра присылала creative для первого survival-входа и не прошла это сравнение.

Исправление читает настройку при реальном запуске, до функций загрузки, плагинов
и приёма игроков. Новые Java и Bedrock игроки используют текущее общее значение;
сохранённый режим не заменяется. Низкоуровневые тестовые конструкторы без startup
сохраняют свой прежний default. `force-gamemode` этим изменением не реализован.
Проверка реального Bedrock-клиента и вся грамматика properties остаются отдельными
задачами; Java-записи их не доказывают. Загрузочный режим не перечитывается при
каждом входе и поэтому не затирает последующий `/defaultgamemode`.
