# Выбранный рецепт белой бетонной плиты: книга777

Обычные сетевые действия на официальном26.3; непрозрачный JAR SHA1
`33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`. Без распаковки, исходников,
отчётов и выгрузок таблиц. Сохраняются только выбранные записи с результатом
`white_concrete_slab`, ответы-подсказки и собственные снимки инвентаря.

Свежему игроку в выживании после `recipe take McsaProbe *` выдан1блок
`white_concrete`. Пришли два показа: shaped3×1→6плит и stonecutter→2плиты.
Первый runner ошибочно ожидал один показ по предмету результата и остановился;
эта неудачная запись сохранена. Второй выбирает для запросов именно shaped.
Показ камнереза не доказывает реальную операцию камнереза.

`recipe take ... minecraft:white_concrete_slab`, затем `recipe give` с тем же
именем повторно прислали shaped с тем же DisplayID в этой сессии. Это связывает
имя команды с показом. Число1693 — наблюдённый номер показа соединения;
оно не должно становиться внутренним ID рецепта нашего ядра.

С1блоком запрос autofill возвращает `craft_recipe_response` с той же shaped
формой: итог и сетка пусты, блок остаётся в панели. После добавления ещё8блоков
обычный запрос заполняет средний ряд slots4/5/6 по1; в панели остаётся6.
Повторный обычный запрос (`makeAll=false`) увеличивает каждую клетку1→2;
в панели остаётся3. Запрос `makeAll=true` увеличивает2→3 и опустошает панель.
Три забора результата дают курсор6→12→18 и пустую сетку. Все7проверок
прошли на finalofficial05; прежние6/7checksзаписи сохранены отдельно.
Сервер exit0, собственная группа исчезла,26044освободился.
Это не GUI и не проверка полного порядка пакетов. Числовые display/group
при сравнении разных серверов нельзя считать общей внутренней идентичностью.

[Выбранный fixture](testdata/white-slab-recipe-book-777.json).
`probe_recipe_book_white_slab_777.py` по умолчанию показывает план;
реальный запуск требует `--run --jar <JAR> --data <закреплённые JSON>
--output <новая папка>`. Для privatecore вместо `--jar` нужны
`--test-binary <бинарник> --binary-sha256 <SHA256>`; его фиксированный порт26026. Проверяются SHA1 JAR и SHA256 разрешённых JSON.
Используется отдельный новый мир и собственные конфигурации. Эта наблюдательная работа Rust не меняет;
готовность книги нашего ядра не заявляется. На старом фиксированном core
выбранный показ не появился после выдачи блока: probe сохранил ожидаемую
ошибку selected_entries=[] и штатно остановил сервер. Старые записи
не перезаписывались.

## Проверка нашего выбранного shaped-рецепта

После интеграции **тот же** probe (SHA256
`4149a7c7094448d3baa5ee189c35482f839766312d59c4fabf9221494ab5fde5`)
прошёл7случаев на private777catalog. Все8снимков содержимого окна/курсора
совпали с finalofficial05: подсказка при нехватке, once/repeat/all и расход
9блоков с получением18плит. Выбранная shaped-запись совпала по форме,
входам, результату, станку, категории, требованиям и флагам; ответ-подсказка
также совпал. IDпредметов сравнивались по закреплённым именам.

Локальный DisplayID различается: official1693, ours1478. Группа на проводе
также различается:22и1. Сравнивается наличие группы; числовой индекс группы
не объявляется общим протоколом идентичности между разными серверами.
Связь каждого запроса с выданным DisplayID проверяет сам probe.

Наш shaped-рецепт проверен; показ камнереза и его реальная операция в наше
ядро этой партией не добавлены. Последующее отдельное изменение описано в
[наблюдении камнереза](observations-stonecut-26.3.md). Полный порядок пакетов, GUI, остальные рецепты
и полный26.3 не заявляются. Оба runtime остановились с exit0, свои группы
исчезли, временные порты свободны. До исправления тот же probe завершался
ожидаемой ошибкой отсутствующего выбранного показа; эта запись сохранена.
