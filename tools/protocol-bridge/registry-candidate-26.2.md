# Кандидатные реестры 26.2

Это подготовка собственных таблиц для протокола776. Runtime не использует этот
отчёт; публичный вход и основной игровой профиль26.2 он не включает.

Источник новых JSON — minecraft-data, неизменяемый commit
`924e26d6b3bb8f97a5d1e73d6190b09879c2e1e2`. Все 13 источников, их URL,
размеры и SHA256 перечислены в [отчёте](registry-candidate-26.2.json).
Два источника — закреплённые локальные blocks/items нынешнего ядра775.
Protocol775 и entities775 используют прежние pins проекта.
Чужие реализации, содержимое JAR и mappings не читались.

| Реестр | В775 | В776 | Совпали по точному имени/свойствам | Сменили ID |
| --- | ---: | ---: | ---: | ---: |
| Блоки | 1168 | 1196 | 1168 | 170 |
| Состояния блоков | 29873 | 32366 | 29873 | 5186 |
| Предметы | 1506 | 1537 | 1506 | 1480 |
| Типы сущностей | 157 | 158 | 157 | 27 |
| Частицы | 117 | 125 | 115 | 111 |
| Компоненты предметов | 110 | 111 | 110 | 32 |

В отчёте есть точные двусторонние массивы ID. `-1` означает отсутствие
соответствия; отсутствие объекта нельзя заменять на воздух или пустой слот.
Отдельные списки существующих ID позволяют отличить пропуски от известных
объектов без пары. Состояние блока сопоставляется по имени и всем свойствам.
Это математическое соответствие кандидатных JSON, а не подтверждение сетевых
ID официального776.

Добавлены 28 блоков семейств sulfur/cinnabar, 31 предмет (в том числе
music_disc_bounce, sulfur_cube_bucket и sulfur_cube_spawn_egg), сущность
sulfur_cube, 2493 состояния и компонент sulfur_cube_content.
Полные записи новых объектов и различия общих записей сохранены в content_records.
Различия drops/internalId могут быть простым изменением ссылочных номеров,
поэтому они не объявляются изменениями поведения.

Два старых имени частиц trial_spawner_detected_player и
trial_spawner_detected_player_ominous отсутствуют в776. Сходные новые имена
trial_spawner_detection и trial_spawner_detection_ominous **не получают
автоматического соответствия**. Восемь остальных новых имён: sulfur_bubbles,
noxious_gas, noxious_gas_cloud, geyser, geyser_base, geyser_poof, geyser_plume,
sulfur_cube_goo. Кандидатные particles.json и mapper protocol.json совпали.

Атрибуты намеренно исключены из кандидатных таблиц этого отчёта: protocol.json содержит31 имя,
attributes.json —40 записей без явных числовых ID. Не считать индекс массива ID.
Список31 повторяет известную ошибку кандидата777; нужны отдельные обычные
сетевые наблюдения776. Оба исходных представления сохранены как непроверенные.
Звуки также сохранены только кандидатным списком776, без неподтверждённого
соответствия775.

Позднейшая отдельная официальная проба уже подтвердила40 атрибутов и их ID:
[записи776](testdata/protocol-26.2-observations.json),
[разбор и границы проверки](observations-26.2.md).
Этот кандидатный отчёт оставлен без подмены исходных значений. Отдельный Rust
перевод Attribute ID776 уже использует наблюдения, а не ошибочный mapper31;
остальные реестры и публичный клиентский маршрут776 этим не включаются.

Важные дополнительные наблюдения по данным: slime/magma_cube уже в776 имеют
новые metadataKeys baby/age_locked перед size (индекс size16→18), у bee изменены
размеры. Эти значения пока не подтверждены официальной пробой776. Одинаковая
общая форма Entity Metadata в protocol.json не доказывает одинаковые поля
конкретных сущностей.

Воспроизведение:

```bash
python3 -B tools/protocol-bridge/generate_registry_26_2.py \
  --cache /path/to/registry-26.2-json --download --check
python3 -B tools/protocol-bridge/test_registry_26_2.py
```

Без `--download` генератор работает только с локальным кэшем. При наличии отчёта
он проверяет SHA всех уже закреплённых входов; `--check` сравнивает весь результат
побайтно и ничего не перезаписывает. Для первичного создания отчёта убрать
`--check`. Кэш не входит в Git. Отчёт не подключён к Rust и не увеличивает
исполняемый файл.

Проверено: воспроизводимость без сети, шесть офлайн-тестов генератора,
двустороннее соответствие каждого совпавшего ID. Cargo, игровые серверы и
официальные клиенты в этом этапе не запускались. До runtime остаются
официальные776 наблюдения, динамические реестры, codec и отдельные игровые
проверки. Основной профиль26.2 требует своей реализации механик и сохранений.
