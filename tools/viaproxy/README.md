# Старые Java-клиенты через ViaProxy

ViaProxy — временный мост перед ядром MCSheriffAnya 26.1.2 (протокол 775).
Это отдельная программа Java под GPLv3, не часть ядра MIT. JAR, его зависимости,
настройки и мир хранятся в рабочем каталоге сервера (у `run.sh` — вне репозитория). Исходники ViaProxy/ViaVersion не
используются и не копируются; интеграция написана по публичной спецификации
[HAProxy PROXY v1/v2](https://www.haproxy.org/download/2.9/doc/proxy-protocol.txt).

Нужны Java (рекомендуется 21+) и собранный `target/release/mcsheriffanya`.
Запуск из корня репозитория:

```sh
tools/viaproxy/run.sh 26101 26100
```

Скрипт скачает официальный стабильный ViaProxy **3.4.14** (актуален на
23.10.2026) в `~/.cache/mcsheriffanya/viaproxy/`, если JAR ещё отсутствует.
Он запускает ядро на **127.0.0.1:26100**, ViaProxy на **0.0.0.0:26101**;
игроки подключаются к публичному порту 26101. Скрипт разрешает только
26100–26199, не использует 25565. Ctrl-C завершает оба процесса по их PID.
Логи и PID: `$VIAPROXY_RUN/{core,proxy}.{log,pid}`; каталог по умолчанию
`~/.cache/mcsheriffanya/viaproxy/run`. Не запускайте две копии с одним каталогом.

Переменные: `MCSA_BIN` (абсолютный путь к ядру), `VIAPROXY_CACHE`,
`VIAPROXY_RUN`, `VIAPROXY_JAR` (абсолютный путь к другому официальному JAR),
`VIAPROXY_JAVA_OPTS` (по умолчанию `-Xmx512m`). Данные мира и аккаунтов
сохраняются при повторном запуске. Прочие настройки редактируются в
`$VIAPROXY_RUN/core/config/`; публичный/локальный порт, offline-mode,
PROXY и отключение Bedrock задаются скриптом при каждом запуске.

**Авторизация:** доверенный PROXY-вход автоматически использует чат вместо
configuration-диалога. До `/register <пароль> <пароль>` или `/login <пароль>`
игрок находится в замороженном limbo с темнотой и русской подсказкой; через
90 секунд его отключает ядро. Мир, playerdata и плагины доступны после входа.
Сохраняются premium-проверки, защита операторов и ограничения по реальному IP.
Парольные команды не передаются плагинам и не печатаются в журнале.
Для прямых клиентов такой же режим включается через `auth-mode=chat`.

## Автозапуск ядром

В `config/mcsa.properties`:

```properties
viaproxy=true
viaproxy-port=26101
viaproxy-java=java
viaproxy-memory=512M
auth-enabled=true
```

В `config/server.properties` задайте `server-port=26100` и `online-mode=false`.
Запустите только ядро. Оно принудительно слушает 127.0.0.1 и доверяет PROXY
только от 127.0.0.1. ViaProxy слушает публичный `viaproxy-port`; порты различаются.
По умолчанию `viaproxy=false`, Java не нужна. Для автозапуска нужна Java 17+
(рекомендуется 21); `viaproxy-java` может быть абсолютным путём с пробелами.
`viaproxy-memory` — размер heap в M/G, без `-Xmx`.

Официальный JAR 3.4.14 скачивается по HTTPS в `viaproxy/` относительно рабочего
каталога сервера. Перед каждым запуском проверяется закреплённый SHA-256
`2894bbfb2f4342f8fde887af6c689313efd5b0e46a8006775eea0e21e2948ab5`.
При несовпадении запуск отменяется; удалите JAR для повторной загрузки.
`viaproxy/viaproxy.yml` генерируется ядром; ручные изменения перезаписываются.
Вывод дочернего процесса помечен `[ViaProxy]`; после сбоя допускаются три
перезапуска с задержкой 2/4/8 секунд. При остановке ядро завершает и ожидает
ViaProxy. Отсутствующая Java объясняется русской ошибкой.

Для собственного запуска без скрипта:


```properties
# core/config/server.properties
server-ip=127.0.0.1
server-port=26100
online-mode=false
# core/config/mcsa.properties
proxy-protocol=true
proxy-protocol-trusted-sources=127.0.0.1
```

Возьмите `viaproxy.yml` рядом со скриптом; в каталоге ViaProxy выполните
`java -jar /абсолютный/путь/ViaProxy-3.4.14.jar config viaproxy.yml`.
[Официальная инструкция](https://github.com/ViaVersion/ViaProxy#usage-for-server-owners-config)
также описывает генерацию полного файла с комментариями и режим `cli --help`.

`backend-haproxy=true` передаёт IP клиента ядру; `frontend-haproxy=false`
обязателен для обычного публичного входа. При `proxy-protocol=true` ядро
принимает Java TCP только от точных IP из списка (через запятую, без CIDR),
требует заголовок v1/v2 за 3 секунды и использует переданный адрес для
авторизации, IP-банов и журнала входа. Некорректный список доверия не доверяет
никому. LOCAL/UNKNOWN сохраняют IP прокси. При выключенной настройке поведение
прямого входа прежнее. На Bedrock UDP это не действует. Не открывайте backend
в интернет; любой процесс на доверенном узле способен подставить IP.

По README ViaProxy 3.4.14 поддерживаются Java-клиенты **1.7.2–26.3** и
сервер 26.1.2. Это диапазон транслятора, а не гарантия всех механик ядра.
Клиенты 1.0–1.6.4 имеют только passthrough и к этому серверу не подходят.
Новые блоки/предметы заменяются доступными старому клиенту; интерфейсы,
подписанный чат и моды на старых версиях требуют отдельных
проверок. Bedrock через этот скрипт не предоставляется. Ошибки трансляции
не скрываются; смотрите `proxy.log` и `core.log`.

Воспроизводимая проверка: `NODE_PATH=/путь/к/node_modules node tools/viaproxy/smoke.cjs`.
Нужны mineflayer и vec3; тест использует 26101 и исходный адрес 127.0.0.2.
Тестовый мир должен быть плоским, авторизация отключена, игроки Via120, Via116 и ViaAdmin
добавлены в ops.json (уровень 4). Тест проверяет вход, чат, движение, ломание,
установку блока и повторный вход для 1.20.1 и 1.16.5, затем IP-бан
127.0.0.2 при продолжающемся соединении администратора с 127.0.0.3.

Проверено 23.10.2026 на официальном JAR 3.4.14 (SHA-256
`2894bbfb2f4342f8fde887af6c689313efd5b0e46a8006775eea0e21e2948ab5`):
1.20.1 и 1.16.5 — вход, чат, движение, ломание/установка stone и повторный
вход прошли. Проверены реальные IP 127.0.0.2/127.0.0.3 через ViaProxy,
отклонение первого по IP-бану, прямые status-запросы через заголовки v1/v2
и отказ недоверенному TCP-источнику. Ядро также принимает команды в signed-форме,
которую отправляет транслятор. Парольный диалог в этой проверке был выключен.
Оба процесса завершены через supervisor, порты 26100/26101 освобождены.

Проверка парольного входа (в изолированном свежем мире, `auth-premium=false`,
`debug=true`, backend 26120, публичный 26121):
`NODE_PATH=/путь/к/node_modules node tools/viaproxy/auth-smoke.cjs`.
Проверяет регистрацию, повторный вход, неверный пароль, блокировку чата/команд
и 90-секундный таймаут на mineflayer 1.20.1/1.16.5. Проверяйте отсутствие
тестовых паролей в console/core/ViaProxy logs. Premium-правила проверяются
отдельными unit-тестами auth, без внешнего sessionserver в smoke.
