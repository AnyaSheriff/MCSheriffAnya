# Приёмник отчётов об ошибках

Маленькая отдельная программа для VPS. Серверы MCSheriffAnya, чьи владельцы
включили отправку отчётов, шлют сюда отчёты об ошибках. Приёмник:

- не записывает адрес отправителя ни на диск, ни в журнал. Адрес держится в
  памяти не дольше часа — чтобы один источник не завалил приёмник отчётами:
  с одного адреса и на один номер установки — не больше 20 отчётов в час,
  всего — не больше 500;
- отклоняет неправдоподобное: неизвестный вид, версию не в виде выпуска,
  систему с посторонними знаками, пустое сообщение;
- ещё раз вычищает из отчёта адреса IPv4 и имена в путях `/home/…`, на
  случай если сервер что-то пропустил;
- складывает одинаковые ошибки вместе и считает, сколько раз и на скольких
  серверах они случились. От каждого вида хранит 20 последних отчётов;
- отдаёт сводку и отчёты только по ключу.

## Запросы

| Запрос | Что делает |
|---|---|
| `POST /v1/report` | принять отчёт: 204 — принят, 400 — не тот формат, 413 — больше 256 КБ, 429 — слишком часто, 507 — хранилище полно |
| `GET /v1/summary` | сводка по видам ошибок (TSV), свежие сверху; нужен ключ |
| `GET /v1/report/<подпись>` | отчёты одного вида (JSON); нужен ключ |
| `GET /health` | `ok` |

Ключ передаётся заголовком `Authorization: Bearer <ключ>`.

Отчёт — JSON:

```json
{
  "format": 1,
  "install": "0123456789abcdef",
  "version": "0.0.2-alpha",
  "os": "linux x86_64",
  "kind": "panic",
  "message": "первая строка — по ней ошибки группируются",
  "lines": ["строки журнала перед ошибкой", "…"]
}
```

- `install` — случайный номер установки: 16 шестнадцатеричных знаков.
  Сервер создаёт его один раз. По нему видно, что две ошибки пришли с
  одного сервера, но не видно, с какого.
- `kind` — одно из `panic`, `error`, `bedrock-crash`.
- Ограничения: `lines` — до 400 строк по 1000 знаков, `message` — до 2000
  знаков.

## Сборка

Статическая сборка работает на любом Linux x86_64, в том числе на Debian 13:

```sh
rustup target add x86_64-unknown-linux-musl
cargo build --release --target x86_64-unknown-linux-musl
# готово: target/x86_64-unknown-linux-musl/release/mcsa-logreceiver
```

Собрать можно и прямо на VPS: `apt install cargo`, затем `cargo build --release`.

## Установка на Debian 13

Скопировать на VPS программу и файлы из `deploy/` в одну папку, затем от root:

```sh
sh install.sh
```

Скрипт ставит программу в `/usr/local/bin`, заводит службу
`mcsa-logreceiver` и создаёт ключ для чтения в `/etc/mcsa-logreceiver/token`.
Отчёты лежат в `/var/lib/private/mcsa-logreceiver`. Служба работает под
временной учётной записью и видит только свою папку.

Дальше нужен веб-сервер с HTTPS перед приёмником.

- **Пустой сервер (порты 80 и 443 свободны):** `WEB=caddy sh install.sh`.
  Caddy сам получит сертификат. Журнал запросов у Caddy выключен, пока его не
  включат явно.
- **Уже есть nginx, который делит 80/443 с xray через `stream` по имени
  сайта (как на tg.yebat.su).** Через `stream` адрес отправителя теряется,
  поэтому отчёты принимаются на своём порту **7443** — туда nginx слушает
  сам и видит настоящий адрес. Через 443 остаётся только `/health`, иначе
  через него обходили бы предел на адрес. Сервер MCSheriffAnya шлёт на
  `https://log.sheriffanya.ru:7443/v1/report`.
  1. В DNS завести запись A: `log.sheriffanya.ru` → адрес VPS.
  2. Положить `nginx-log.sheriffanya.ru` в `/etc/nginx/sites-available/` и
     включить ссылкой из `sites-enabled/`. Сначала без блока `ssl`: сертификата
     ещё нет.
  3. В `stream` в `/etc/nginx/nginx.conf` направить имя `log.sheriffanya.ru`
     туда же, куда `tg.yebat.su`: TLS с 443 — в `web_tls`, HTTP с 80 — в
     `web_plain`.
  4. `nginx -t && systemctl reload nginx`, затем
     `certbot certonly --webroot -w /var/www/html -d log.sheriffanya.ru`.
  5. Вернуть блок `ssl`, снова `nginx -t && systemctl reload nginx`.
  6. Если есть фаервол — открыть порт 7443/tcp.
  7. Проверка: `curl https://log.sheriffanya.ru:7443/health` → `ok`.

## Чтение

```sh
curl -H "Authorization: Bearer $(cat ключ)" https://log.sheriffanya.ru:7443/v1/summary
curl -H "Authorization: Bearer $(cat ключ)" https://log.sheriffanya.ru:7443/v1/report/<подпись>
```
