# Полный MapChunk и данные блоков: 775 ↔ 777

Формат конверта — закреплённые protocol.json и
[Wiki Packets, revision3848030](https://minecraft.wiki/w/Java_Edition_protocol/Packets?oldid=3848030).
Палитры/свет описаны в [предыдущем исследовании](light-chunks-26.3.md).
Никакие реализации, JAR-код или дампы реестров не использовались.

## Контекст и проверки

MapChunk переводится через обычный `Outgoing` до сжатия и шифрования.
Вызывающий явно передаёт min_y, количество секций и размер общего реестра
биомов. Ядро берёт их из своих параметров мира и Configuration. Порядок биомов
775/777 одинаков; существующий тест сравнивает записи реестров по именам.
Произвольный пакет без этого контекста отклоняется.

Перевод проверяет высоту, длины и значения heightmaps, палитры, координаты и
дубликаты блок-сущностей, границы NBT и масок света. Поддерживается весь конверт
секции/биомы/heightmaps/данные блоков/свет. Это не обещание поддержки любого
вложенного NBT: незнакомые схемы по-прежнему явно отклоняются.

## Наблюдавшиеся номера

`probe_block_entities.py` ставит 45 названных блоков в отдельном временном мире
официального сервера и читает только записи этих блоков из MapChunk. Секции,
реестры и мировой файл не сохраняются. Обычный piston не дал блок-сущности;
движущийся поршень отдельно не проверялся.

Результат: 44 записи в775 и43 в777. Номера многих записей изменились:
barrel27→26, campfire33→32, decorated_pot42→41, crafter43→42 и другие.
Полная наблюдавшаяся таблица — `../protocol-bridge/block-entity-observations.json`.
Её генерирует `generate_block_entities.py` из собственных сохранённых записей.
Ненаблюдавшиеся ID (в частности10/11 старого реестра) не считаются известными.

Кровать775 имеет BE25, а777 не прислал BE для неё. Дополнительная команда
`execute if block … minecraft:white_bed` подтвердила, что сам блок сохранился.
При переводе775→777 пустая запись кровати удаляется; при777→775 создаётся BE25
для каждого состояния кровати. Состояния взяты только из разрешённого
`tools/data/blocks.json`; генератор фиксирует его SHA256. Непустые неизвестные
данные кровати не удаляются молча — перевод возвращает ошибку.

## Разрешённые NBT-схемы

- Отсутствующие данные или пустой Compound для наблюдавшихся типов.
- Обычный текст обеих сторон таблички, свечение, цвет красителя и воск.
  Строковые messages/filtered_messages содержат ровно4 элемента.
- Levels и шесть обычных имён эффектов маяка.
- Пустые Items костра/полки, align_items_to_bottom полки.
- Пустые components знамени и Age врат Энда.

Неизвестные поля, повторные ключи, сложные текстовые компоненты, предметы на
полках/кострах, данные существ в спавнерах и прочие схемы пока не переводятся.
Block Entity Data использует тот же проверенный переводчик. Отдельное
обновление удалённой в777 BE кровати пока возвращает явную ошибку: одиночный
wire-переводчик не умеет выдавать ноль пакетов. Первоначальный MapChunk кровати
обработан отдельно, как описано выше.

## Проверка ядра и клиента

`chunk_compat_tests.rs` вызывает настоящий builder мира/чанков: каменная
площадка, сундук, бочка, оранжевая табличка с текстом, кровать, маяк и8 соседних
чанков. Сравнивает проход через шифрованное соединение и явный перевод,
проверяет обратное направление. `export_chunk_client_probe` экспортирует
ТОЛЬКО наши14 пакетов Play; `export_registry_client_probe` — наши Configuration.

`probe_registry_client.py --play-packets …` передаёт эти данные обычному
официальному клиенту26.3 с синтетическим offline-профилем в изолированном Xvfb.
Условия успеха: Configuration ACK, подтверждение переноса с точной позой,
Player Loaded и отсутствие ошибок обработки пакетов/чанков в журнале клиента.
Этот тест не проверяет полноценный серверный цикл, инвентарь, PvP или любой
возможный блок-сущность. Допуск новых клиентов остаётся закрытым.


## Найденная при проверке ошибка Login

Кандидат protocol.json сохраняет старые i8/u8 для текущего/предыдущего режима.
Wiki3848030 в разделах Login/Respawn явно указывает VarInt; previous имеет
значение0 для отсутствия и ID+1 для заданного режима. Официальные входы в775
и777 подтвердили это: первый вход creative дал хвост `01 ff` / `01 00`,
после creative→survival и повторного входа — `00 01` / `00 02`.

Первый запуск клиента отверг исходный Login с previous=ff: VarInt съел
следующий байт, и в конце пакета не хватило bool. Исправленный Login переводит
режимы явно в обоих направлениях; родной775 по-прежнему отправляет byte/-1.
Новая ошибка не связана с чанками, но мешала проверить их настоящим клиентом.
Сохранённые `play-login-*-none.bin` / `*-previous-creative.bin` получены нашей
пробой, не из реализации. Для всех5 предыдущих режимов есть независимый тест
ожидаемых байтов. Respawn остаётся отдельным неподдержанным пакетом.


Финальная проверка (18 октября): 2506 тестов ядра + 39 протокольных +
11 seedmap = 2556 успешных, 73 пропущены. Clippy с `-D warnings` и release
build прошли. Официальный клиент 26.3 принял финальные 27 реестров и девять
чанков из Rust, подтвердил точную позицию и загрузку игрока; ошибок обработки
пакетов не было. Это проверка подготовленного обмена, а не полного игрового
цикла. На запущенном ядре 25 родных чанков 775 побайтно совпали с предыдущей
сборкой b31f643. Все 11 проверок допуска/статуса прошли; вход разрешён только
для 775. Свежие боевые записи на этом этапе не выполнялись.
