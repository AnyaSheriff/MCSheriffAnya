# Смена сделки при одинаковой оплате

Собственная сетевая проба `tools/protocol-bridge/probe_trade_selection.py`
прошла на официальных 775/777 и тестовом ядре с клиентами 775/777.
На каждой цели: 12 наблюдений выбора сделки, 6 контрольных точек; все четыре
процесса сервера завершились с кодом 0. Порты проб 26024/26026 освобождены.

Мир и житель созданы пробой. Две заданные нами сделки: 64 изумруда → 64 алмаза
и 1 изумруд → 1 хлеб. В обоих случаях автозаполнение оставляет во входе те же
64 изумруда. До исправления `merchant::select_trade` при неизменных входах
сохранял прежний результат, а оплата списывалась по новому выбранному номеру.
В результате дорогой товар можно было получить по дешёвой цене.

Теперь выбор пересчитывает результат независимо от изменения входов. Перед
выдачей `take_result` ещё раз вычисляет результат по текущим предложениям и
оплате, не считая сохранённый предпросмотр основанием для выдачи.

| Контрольная точка | Изумрудов осталось | Хлеб | Алмазы | Использований дорогой / дешёвой сделки |
|---|---:|---:|---:|---:|
| Смена дорогой на дешёвую, ложное предсказание 64 алмазов | 63 | 1 | 0 | 0 / 1 |
| Повторное открытие и ещё один щелчок | 62 | 2 | 0 | 0 / 2 |
| Обратная смена на дорогую сделку | 0 | 0 | 64 | 1 / 0 |
| Повторный щелчок при пустой оплате | 0 | 0 | 64 | 1 / 0 |
| Только 63 изумруда, дешёвая сделка недоступна | 63 | 0 | 0 | 0 / 0 |
| Shift после смены дорогой на дешёвую | 0 | 64 | 0 | 0 / 64 |

Эти числа, а также входы/выходы всех 12 выборов совпали на четырёх целях.
Числа использований прочитаны из настоящего пакета Merchant Offers после
повторного открытия, а не вычислены пробой из ожидаемой цены. Сырые пакеты,
команды, снимки инвентаря и логи сохранены в handoff-каталоге
`verification-priority-layouts/trades-{official,core}{775,777}`;
общая сводка — `trade-selection-comparison.json`.

JAR проверены по SHA1: 775 — `97ccd4c0ed3f81bbb7bfacddd1090b0c56f9bc51`,
777 — `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`.
Тестовый бинарник — SHA256
`de52f966ef9f07eec56a33b91e41d1c6905f61e3d1992d5c08ffacda064c2d5c`.
JSON проверены по закреплённому manifest; содержимое JAR и чужой код не читались.

Эта сборка содержит торговые исправления. Проба не проверяла последующие
изменения возврата во вторую руку и формата сохранения курсора. Четыре
торговые Rust-регрессии/проверки сохранности окон прошли в общем тестовом
прогоне, но тот прогон целиком не был зелёным: повторный обмен брони выявил
ошибку добавления в существующую стопку второй руки. Отдельная официальная
проба подтвердила ожидаемое поведение; исправлен общий `Inventory::put`,
а не ослаблено ожидание теста. См. [наблюдения второй руки](inventory-armor-edges.md).
Итоговые tests/Clippy/build всего batch учитываются
отдельно; успешные сетевые сессии их не подменяют.

Проба подтверждает только эти действия с заданными предложениями. Внутренний
предпросмотр сервера по сети не подменялся: его устаревшее состояние отдельно
проверяют Rust-регрессии в `dupe_tests.rs`. Сетевой HashedSlot здесь проверяет
недоверие к предсказанию клиента. Это не доказательство полной совместимости
торговли, отсутствия других дюпов или устойчивости сохранений к аварии.
