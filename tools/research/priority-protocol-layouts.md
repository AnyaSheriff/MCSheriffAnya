# Выбранные клиентские протоколы: точные JSON-схемы

Это подготовка переводчиков, **не включение поддержки клиентов**. Отчёт не
доказывает правильность поведения сервера или всех реестров предметов/блоков.

По требованию Ани «26.2 тоже делай» от 20 октября 2026 к шести приоритетным
клиентам добавлен 26.2. Основной игровой профиль 26.2 нужен отдельно:
наличие его сетевых схем не реализует правила игры или перенос мира.

`tools/protocol-bridge/testdata/priority-protocol-layouts.json` содержит Login,
Configuration и выбранные пакеты Play: Join/Respawn, чанки/свет, движение,
инвентарь/рецепты и сущности. Для каждого пакета записаны ID, точная JSON-схема,
транзитивные именованные типы и различия относительно протокола 775.
Схемы и наборы типов хранятся один раз; ссылки на них — первые 16 hex-символов
SHA256 с проверкой коллизий. Источники имеют **полный SHA256**, размер и URL.

Числа протоколов сверяются с отдельным `version.json` каждой точной версии.
26.1 здесь — название набора JSON для 775, не изменение заявленной основной
версии ядра 26.1.2. Клиент 1.17 не подменяется клиентом 1.17.1.

Источники: только разрешённые minecraft-data JSON. Для 340 сохранён уже
используемый pin `201ca802a1b2c968b02e7fa5b31dd74e8bff3d8b`, для базовой wire-схемы
775 — `23303d2350177f2084f94cd38e5d7c8e54dfc8d3`. Остальные данные закреплены на
`924e26d6b3bb8f97a5d1e73d6190b09879c2e1e2`. Это разные источники намеренно:
одноимённые старые схемы в новом commit отличаются, существующие проверенные
источники нельзя незаметно заменить. Все 19 точных URL доступны в `sources`.
Исходники библиотек и серверов, mappings, содержимое JAR не читались.

Дополнение 26.2 использует собственные `pc/26.2/version.json` и
`pc/26.2/protocol.json` из того же закреплённого источника. Первый явно задаёт
`minecraftVersion: "26.2"` и `version: 776`; маршрут взят из `dataPaths.json`.
SHA256: version — `e4a731efdc228a6dafd61eb842e8eb76f9d6b766979254d743e161b86d7c1d0c`,
protocol — `a6c9bd7240f74b94eb0d9b1497294e4cfaa4bb02c0023817c952429149e2d50c`.
Это сведения закреплённых JSON, не результат входа официального клиента.

Итоговый отчёт: 339 схем, 958 выбранных пакетов, 499176 байт; SHA256
`c534199a125b49c8739aa9c0ac12502732b145bbeedc488d76fdeaadd40e6b2e`.
При добавлении 776 все восемь прежних версионных записей, прежние источники,
схемы и наборы типов сохранены без изменений. Повторная генерация совпала
побайтно. Ни клиентский маршрут 776, ни основной профиль 26.2 этим этапом
не включены; игровых или сетевых проверок 26.2 этот отчёт не содержит.

## Воспроизведение

Из корня миграционной ветки:

```sh
python3 tools/protocol-bridge/generate_priority_layouts.py \
  --cache /home/lenox/.local/share/mcsa-java-26.3-probe/priority-json \
  --download --check
```

`--download` скачивает только отсутствующие JSON по закреплённым URL.
Существующий отчёт служит также lock-файлом SHA256 источников: повреждённый кэш
или скачанный файл с другим хешем отклоняется. `--check` повторно строит отчёт и
сравнивает байты. Без `--check` генерируется новый отчёт, но существующие хеши
источников всё равно проверяются. Кэш не входит в репозиторий.

## Что необходимо учесть в переводчиках

- 340 и 754 используют `window_click.action: i16` и подтверждения транзакций.
  В **755 (именно 1.17)** уже есть `changedSlots/cursorItem`, но ещё нет `stateId`.
  Его `window_items` также без `stateId/carriedItem`. Отдельная схема необходима.
- 763 ещё не имеет Configuration. Join несёт NBT `dimensionCodec`; в Respawn
  идентификаторы измерений передаются строками. Нельзя просто переименовать
  пакеты современной Configuration.
- 767 уже имеет Configuration и компонентные `Slot`; совпадение наружной
  схемы инвентаря не означает совпадение вложенных типов/компонентов.
- 774 ближе к 775: `HashedSlot`, `MovementFlags`, `lpVec3` уже присутствуют.
  Однако среди выбранных пакетов меняются 7 прямых схем и 17 наборов зависимых
  типов; требуется перевод содержимого, а не только ID.
- У 776 среди выбранных пакетов нет отличающихся ID или отсутствующих
  одноимённых пакетов относительно 775, но отличаются три прямые схемы:
  Login Success, Play Join и Entity Attributes. Ещё 12 пакетов имеют отличия
  зависимых типов: предметы/инвентарь, рецепты, metadata и торговля.
  Совпадение ID не разрешает передавать их содержимое без собственного
  проверенного перевода; реестры и непрозрачные данные требуют отдельных проб.
- Чанки 340/754/755/763/767/774 различаются: маски, биомы, heightmaps, свет,
  block entities. Поле `chunkData` остаётся непрозрачным буфером в этих JSON;
  его внутренний формат надо отдельно подтверждать собственными наблюдениями.
- `schema_changed` сравнивает точный JSON, включая имена полей и представление
  алиасов. Оно **не доказывает** изменение байтов. Обратное тоже важно:
  равная схема не доказывает равенство реестров, NBT-содержимого или механики.
  Сравнение по одинаковому имени пакета не устанавливает соответствие
  переименованных/разделённых пакетов.
- `native_types`/`external_native_types` обозначают примитивы и внешние кодеки,
  семантика которых не раскрыта в этих JSON. Их реализации не использовались.

Профиль основной версии игры остаётся общим для всех клиентов. Таблицы выше
описывают представление по сети, а не разные правила игры для разных клиентов.
