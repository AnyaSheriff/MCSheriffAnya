# Вход для Bedrock: план

Решения пользователя от 2026-09-24:

- Версия Bedrock — только парная к Java 26.1.2. Это Bedrock 26.10–26.13,
  протокол 944: обновление Tiny Takeover вышло 24 марта 2026 сразу как
  Java 26.1 и Bedrock 26.10 (minecraft.wiki, «Tiny Takeover» и «Bedrock
  Protocol version numbers»).
- Вход сначала без проверки, как `online-mode=false`. Проверка подписи
  Xbox Live — отдельным шагом.
- Таблицы блоков и предметов — minecraft-data (`data/bedrock/1.26.10`,
  соответствие блоков `blocksJ2B` от 1.26.0) и вики. Недостающее
  сопоставляем сами. Данные и код GeyserMC не берём; документацию GeyserMC
  пользователь разрешил (сообщение от 2026-09-24).
- Код ядер, прокси и протокольных библиотек не читаем. Сторонний
  клиент-робот допустим как чёрный ящик, как mineflayer для Java.

## Шаги

1. **Данные.** Скрипт в `tools/` скачивает из minecraft-data описание
   протокола 1.26.10 и таблицы блоков, предметов и соответствия. Из них
   собираются таблицы в коде, как `blocks_table.rs` у Java. Проверить по
   первоисточникам, как нумеруются блоки в сети (по порядку или хэшем).
2. **RakNet поверх UDP** (`src/bedrock/raknet.rs`, свой, с нуля):
   - пинг, чтобы сервер был виден в списке серверов Bedrock;
   - рукопожатие, кадры, надёжная и упорядоченная доставка;
   - разбиение больших пакетов, ACK/NACK, повторы.

   Порт — настройка в `mcsa.properties`.
3. **Сессия.** Пакеты NetworkSettings и Login (JWT без проверки), сжатие,
   шифрование (ECDH P-384 и AES — уточнить режим), PlayStatus.
4. **Вход в мир.**
   - Пакеты наборов ресурсов (пустые) и StartGame.
   - Справочники: предметы, биомы, творческий инвентарь по минимуму.
   - Чанки из нашей модели мира: подчанки с палитрами, перевод
     блоков Java→Bedrock.
   - Появление игрока (PlayStatus о спавне).
5. **Игра вместе с Java-игроками.**
   - Движение (PlayerAuthInput), видимость игроков в обе стороны, чат, время суток.
   - Ломание и установка блоков, инвентарь по минимуму.
6. **Проверка подписи Xbox Live** (ключ Mojang, цепочка JWT).

## Состояние на 2026-09-24

Сделано и проверено роботом (`tools/measure/bedrockbot.js`,
`tools/measure/bedrockbuild.js`) вместе с роботом Java:

- пинг и список серверов, вход без проверки Xbox Live, сжатие;
- StartGame, реестр предметов, творческий инвентарь (1496 предметов Java,
  которые есть у Bedrock; цвет кроватей и флагов — в метаданных),
  определения биомов (имя, номер, климат, цвет воды), чанки;
- творческий режим: полёт, мгновенное ломание (UpdateAbilities);
- ломание и установка блоков — из InventoryTransaction и из
  PlayerAuthInput (block_action, item_interact); Java видит сразу;
- игроки в обе стороны, скины: свой у Bedrock (из ClientData), у игрока Java
  — скачанный PNG (свой разбор PNG), до загрузки — заглушка; уход — из мира
  и из Tab;
- RakNet: окно перегрузки и срок повтора по времени отклика, иначе медленный
  клиент тонул в повторах и обновления опаздывали на секунды.

Добавлено позже в тот же день (робот `tools/measure/bedrockinv.js`):

- инвентарём распоряжается сервер (`server_authoritative_inventory`):
  Item Stack Request — взять, положить, поменять, выбросить, уничтожить,
  предмет из творческого меню — с откатом при отказе; номера стопок;
  Inventory Content / Inventory Slot; выбор слота (Mob Equipment);
- файл игрока тот же, что у Java: место, поворот, режим, инвентарь;
  впервые зашедший — в творческом, как игрок Java;
- выживание: блок из руки расходуется, из сломанного выпадает предмет
  (как у Java: камень рукой — ничего), лежащие предметы видны, подбор;
- команды из клиента: список команд (Available Commands) и Command
  Request через общий обработчик; поручения give, clear, tp, kick; смена
  режима на лету;
- предмет в руке виден в обе стороны.

Не сделано: шифрование, проверка Xbox Live, здоровье и урон (их нет и у
Java), крафт, сундуки, взмахи рук и позы, сущности кроме игроков, блоки с
данными (таблички, сундуки). Без шифрования робот входит; идёт ли без него
настоящий клиент — проверяется живым входом. Шифрование делать вместе с проверкой Xbox
Live.

Проверки: робот-клиент Bedrock как чёрный ящик и живой клиент
пользователя. Готово, когда Bedrock-игрок заходит, видит наш мир и
Java-игроков, ходит, пишет в чат, ломает и ставит блоки.
