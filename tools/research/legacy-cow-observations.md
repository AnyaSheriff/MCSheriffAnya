# Cow340: наблюдения перед переводом living entities

2026-10-20. Это запись поведения официального1.12.2 через собственный сетевой
клиент, а не готовая поддержка мобов в legacy adapter. Игровая логика остаётся
общей для всех клиентов. Pig и zombie в данный этап не входят.

## Источники и воспроизведение

`tools/protocol-bridge/probe_legacy_cow.py` использует существующий `Probe` из
`probe_legacy_session.py`; новый общий сетевой клиент не создаётся. На сети
metadata сохраняется целиком, без заранее выбранных индексов здоровья/возраста.
Разбор полей в fixture сделан после записи по сериализаторам закреплённого JSON.

- Официальный JAR1.12.2 SHA1:
  `886945bfb2b978778c3a0288fd7fab09d315b25f`. Только обычный запуск,
  без распаковки/декомпиляции/отчётов.
- Protocol JSON: `legacy-sources-1.12.2.json`, commit
  `201ca802a1b2c968b02e7fa5b31dd74e8bff3d8b`, SHA256
  `2dad4c918f6bd4492bfa8159b4db6ffbbf8f088b628258f03d437b0c0b760af9`.
- Cow ID92 подтверждён pinned entities1.12 JSON и живым Spawn Living.
  Старый entities JSON не содержит индексов metadata.
- Полная запись вне репозитория:
  `~/.local/share/mcsa-handoff/verification-legacy-cow/official340/result.json`,
  SHA256 `cb81d05649deca06acd5ffa5956a13d023d73cc2d9067eaea7395883bd3954c1`.
- Переносимая fixture: `tools/protocol-bridge/testdata/legacy-cow-observations.json`.
  Она содержит52события выбранных коров, raw payload, разобранные metadata,
  attributes, команды и ограничения. Остальные сущности мира остаются только
  в полной исходной записи.

Запуск: `python tools/protocol-bridge/probe_legacy_cow.py --jar <официальный
server.jar> --data <проверенный legacy-json> --output <новый каталог>`.
Порт фиксирован26025; процесс ограничен первыми2доступнымиCPU. Ни Cargo, ни
core-процесс одновременно не запускались. После записи сервер остановлен,
exit0. Общие/боевые серверы не затронуты.

Площадка289блоков bedrock наY63 создаётся после входа, когда чанки загружены.
Игрок в creative, `allow-flight=true`; raw клиент не симулирует физику игрока.
Появление обычных мобов выключено, но ранее созданные сущности мира не считаются
частью авторского сценария. Команды и служебные сообщения сохраняются.

## Что подтверждено записью

**11проверок PASS**: вход/площадка; взрослая cow; baby; metadata после Health4;
speed0.31; абсолютный teleport; падающая cow; Remove при выходе за дальность;
возврат тех же трёх ID; head rotation; relative motion.

| Поле/пакет | Наблюдение |
|---|---|
| Adult Spawn Living | ID47, type92, (3.5,64,0.5), нулевая скорость |
| Baby Spawn Living | ID48, type92, (6.5,64,0.5), Age:-24000 |
| Health | index7 / serializer2 float; Health4 даёт только `070240800000ff` |
| Baby | index12 / serializer6 bool; единственная разница начальных adult/baby metadata —0→1 |
| NoAI | index11 / serializer0 byte; adult/baby с NoAI1 имеют1, AI падающей cow имеет0 |
| Silent | index4 / serializer6 bool=1 во всех трёх; отдельного переключения Silent не было |
| Скорость | `generic.movementSpeed` base0.31, без modifiers, после entitydata |
| Поворот | tp90°/pitch10° даёт Teleport angles[64,7], затем HeadYaw64 |
| Поворот180° | Teleport angles[128,0], затем HeadYaw128 |
| Движение | наблюдены Relative Move, Teleport, Velocity; MoveLook не получен |
| Выход из дальности | Destroy включает47/48/55 |
| Возврат | снова Spawn Living тех же ID, включая прежние UUID и изменённые Health/позиции |

NoAI сравнивался между двумя отдельными взрослыми cow с разной начальной высотой;
это свидетельство соответствия поля, но не изолированное переключение одного ID.
Здоровье подтверждено отдельной командой на том же ID. Возраст — сравнением
взрослого и телёнка, другие начальные metadata у них полностью совпали.

Spawn Living содержит полную metadata, затем сервер повторяет её отдельным
Metadata. Позднее air index1 меняется с0 на300. Нельзя считать начальное значение0
полным описанием семантики поля. При возвращении adult inline metadata сохраняет
Health4, baby сохраняет возрастной флаг.

Падение AI cow сY70 доY64 записано без Motion NBT. Оно даёт Health7 и status2
после удара о площадку. Это дополнительное наблюдение старого сервера, **не**
доказательство, что каждый modern DamageEvent можно заменить status2. У падающей
cow при повторном Spawn Living скоростьY=-627/8000 на опоре; не объявлять этот
факт ошибкой физики или требованием обнулять скорость.

## Граница следующей реализации

Собственный modern sender отдаёт cow kind30, health9/type3, mob_flags15/type0,
baby16/type8. Перевод этих проверенных полей можно отделить от item metadata,
обобщив существующий ограниченный tracker на `Item | Cow`. Collect должен
продолжать принимать только Item; attributes — living/своего игрока.

Неизвестные поля/типы/значения должны оставаться явным отказом. Имена, эффекты,
age_locked, варианты, death pose, звуки, урон, анимации, XP, equipment и правый
клик требуют отдельных решений/наблюдений. Сохранить действующее высотное окно
и проверки скоростей, не менять игровую логику ради старого клиента.

## Настоящий клиент: пустая inline metadata

После official-наблюдения существующий `probe_legacy_client.py` получил
необязательный `--cow-fixture`. Он загружает прежний собственный мир, посылает
Spawn Living с terminator255, а потом отдельную записанную Metadata. На каждой
стадии ждёт keepalive ACK и сохраняет снимок только собственного Xvfb.

Итоговая запись `verification-legacy-cow/client-empty-inline-2`:
**15сетевых проверок PASS**, включая5стадий cow. Report SHA256
`cb01e372e8bc92d0ee375fc75d987098acca64a5fd4e839b3105b215b29b1645`.
Все5PNG лично просмотрены, вывод отдельно в `visual-review.json`:

1. `cow-baseline.png`: коров нет.
2. `cow-empty-inline.png`: две взрослые коровы после Spawn Living сff.
3. `cow-observed-metadata.png`: одна взрослая и один телёнок после отдельной
   полной Metadata.
4. `cow-head-relative.png`: взрослая заметно сместилась на0.5блока, положение
   головы изменилось; телёнок остался.
5. `cow-removed.png`: обе коровы исчезли.

Таким образом, пустой inline список и следующий отдельный Metadata пакет
**приняты настоящим клиентом340 и правильно отображены** в данном сценарии.
Это не утверждение, что официальный сервер сам отправляет пустую metadata.
Игровой маршрут ядра здесь не запускался.

Первый запуск `client-empty-inline` сохранил15PASS, но снимки перекрывались
Game Menu из-за отсутствия фокуса в Xvfb; его не считаем чистым визуальнымPASS.
Повтор использует `pauseOnLostFocus:false` только временного тестового профиля.
Окна на рабочем столе не открывались. Java/Xvfb после проверки отсутствуют,
порт26025 свободен. Автоматический report оставляет render review `pending`;
отдельный `visual-review.json` фиксирует последующую ручную оценку снимков.

Core-сравнения, Cargo, Rust правок, same-dimension respawn или теста боя в данном
этапе не было.11проверок относятся к official340,15 — к отдельному настоящему
клиенту на авторском packet fixture. Готовность полного legacy gameplay из них
не следует. Здоровье не проверяется визуально: стандартный HUD его не показывает.
