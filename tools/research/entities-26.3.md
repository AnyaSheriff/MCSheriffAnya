# Сущности и Respawn775↔777

Источники: закреплённые JSON из `candidate-sources-26.3.json`, собственные
наблюдения `probe_entities.py`, официальное
[описание26.3](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3).
Чужие реализации не использованы. Официальные JAR исполняются в отдельных
временных каталогах, код/датапаки из них не извлекаются.

`generate_entity_layouts.py` проверяет SHA-256 исходных JSON, сопоставляет поля
metadata по имени для157общих типов и пишет список нового контента отдельно.
У slime/magma_cube поле size переходит с16на18, появились baby/age_locked.
В обратном направлении новые поля пока отвергаются, а не удаляются.

`entities::Tracker` хранит типы сущностей отдельно для каждого Outgoing.
AddEntity регистрирует тип после успешного перевода; RemoveEntities удаляет,
Respawn при смене измерения очищает остальные сущности и сохраняет игрока.
При Respawn в том же измерении записи сохраняются. Предел65536сущностей;
ошибка/обрезанный пакет не меняет учёт. Родной775проходит прежним путём.

AddEntity переводит EntityType, а для falling_block ещё BlockState в data;
остальные data остаются динамическими ссылками/направлениями. Координаты
проверяются на конечность, LPVec3 разбирается по длине без изменения чисел.
Respawn использует тот же проверенный SpawnInfo, что Login: optional previous
mode777 равен0(None) либо ID+1,775использует255(None)/ID. Signed sea level,
место смерти и флаги сохранения данных не теряются.

Metadata разбирается до255, с запретом повторных индексов и неизвестных полей.
Есть примитивы, простые имена, Slot, BlockState, позиции/вращения, UUID-ссылка
владельца и ограниченные значения перечислений. Динамические варианты требуют
явного общего порядка реестра и проверки его размера. Painting допускает
только ссылку на общий реестр, не inline-определение. Полный профиль, данные
жителя и частицы пока не реализованы; список частиц допускается только пустой.
Таким образом, это ещё не поддержка любых metadata/всех мобов26.3.
[проверить] Остальные значения перечислений и сочетания типов с полями
конкретных сущностей вне перечисленных контрольных случаев требуют отдельных
живых проб перед включением полноценного маршрута26.3.

## Независимые записи

Официальные775/777: armor_stand, cow, slime, magma_cube, falling_block,
item, arrow, painting, wolf, enderman, block_display; четыре перехода между измерениями в разных
режимах игры. `testdata/entity-observations.json` хранит исходные пакеты.
При сравнении появления нормализуется только случайный UUID сущности;
ID, положение, скорость, тип и data не подменяются. Metadata и Respawn
сравниваются побайтно в обоих направлениях.

Первый777запуск отверг вход: whitelist теперь включён по умолчанию.
В изолированном тесте задано white-list=false. Первый falling_block оказался
песком: в26.3поля состояния Name/Properties переименованы в id/properties.
Команда исправлена отдельно для777, и проба проверяет, что сервер действительно
прислал oak_log[axis=x]. Неудачные логи сохранены рядом с успешными.

Проверка ядра использует настоящие builder-ы SpawnInfo, мобов, чанков и слотов
через шифрованный TCP. Экспорт только НАШИХ пакетов предназначен для реального
клиента26.3 в изолированном Xvfb: два Respawn, возврат в Overworld, повторные
чанки, два подтверждения телепорта, три моба, ответ Ping после всех пакетов.
Это проверка чтения пакетов; игровой вход26.3остаётся закрыт.

Дополнительная проба bamboo_planks подтверждает: OptionalBlockState использует
0для отсутствия и прямой ID в остальных случаях. Ошибка с прибавлением единицы
исправлена до финальной проверки;27(775) переводится в28(777), не в27.
