# Configuration: реестры Java26.3

Источники — только разрешённые страницы Wiki, закреплённые JSON формата
протокола и наблюдение за обычным официальным клиентом. Код/JAR не читались
и не распаковывались; официальные реестры/датапаки не выгружались.

- [Registry Data](https://minecraft.wiki/w/Java_Edition_protocol/Packets?oldid=3848030)
  и [Registries](https://minecraft.wiki/w/Java_Edition_protocol/Registries?oldid=3749652):
  ID определяется порядком записей; отсутствие NBT требует согласованного known pack.
- [Биомы](https://minecraft.wiki/w/Biome_definition_%28Java_Edition%29?oldid=3848210):
  в26.3snap4 удалены `spawners`, `spawn_costs`, `creature_spawn_probability`.
  Последнего поля наш builder не отправлял; остальные два убраны только для777.
- [Отделка брони](https://minecraft.wiki/w/Armor_trim_definition?oldid=3791545):
  `asset_name` заменён на `palette_id`; путь палитры теперь `minecraft:trim/<материал>`.
- [Измерения](https://minecraft.wiki/w/Dimension_type?oldid=3650747):
  с26.2 `infiniburn` принимает список ID. В777 передаём явный список блоков,
  соответствующий нашей логике `src/fire.rs`, вместо ссылки на отсутствующий тег.
  Старый формат775 сохраняется. Первый клиентский прогон подтвердил, что777
  отвергает неразрешимый `#minecraft:infiniburn_*`.

Остальные определения отправляются из наших существующих builders. Это не
копия всех ванильных значений и не заявление о полном соответствии игровой
механики. Новое содержимое26.3 ещё предстоит реализовать.

`mcsa_protocol::registry` ограничивает размер пакета, количество/глубину узлов
NBT, массивы и число записей; проверяет идентификаторы, дубликаты, хвосты,
обрезанные поля. Порядок записей и пользовательские namespaces сохраняются.
Внутри NBT проверяются границы, но не конкретные схемы Minecraft. Подготовку
содержимого для версии клиента делает ядро. Обобщённый `wire::translate`
по-прежнему отвергает произвольный RegistryData между версиями.

Ядро передаёт25реестров для775 и27для777 с полным NBT; отсутствие определения — ошибка,
а не попытка взять запись из known packs. Запись готового реестра проверяет
версию клиента до отправки, затем использует обычные сжатие и шифрование.

## Воспроизведение клиентской проверки

На Linux нужны Java25, Xvfb и графические библиотеки. Все каталоги отдельные.
Сначала, когда никакие black-box серверы/клиенты не работают:

```sh
cargo test --release export_registry_client_probe -- --ignored
python3 tools/protocol-bridge/prepare_registry_client.py --output /tmp/mcsa-client-26.3
python3 tools/protocol-bridge/probe_registry_client.py \
  --client-dir /tmp/mcsa-client-26.3 --packets tmp/registry-client-26.3.json \
  --output /tmp/mcsa-registry-result --port 26012
```

Экспорт содержит только НАШИ31пакет: brand, KnownPacks,27реестров, теги,
FinishConfiguration. Синтетический loopback-сервер передаёт их официальному
клиенту; успех — его AcknowledgeFinishConfiguration. После этого соединение
закрывается. Это проверка принятия конфигурации, **не входа в игровой мир**.
Клиент использует вымышленный offline-профиль без настоящих credentials;
в журнале возможны ожидаемые отказы авторизации Realms/профиля.

Клиент запускается через Xvfb без унаследованных Wayland/Display-переменных,
со звуком null. Пользовательские настройки, миры и аккаунты не читаются.
Все процессы своей группы завершаются по сохранённому PID; журнал и результат
сохраняются в `--output`. Не запускать одновременно со сборкой ядра.

## Преобразования блоков

[Block transformer](https://minecraft.wiki/w/Block_transformer_definition?oldid=3845159)
и [Snapshot10](https://minecraft.wiki/w/Java_Edition_26.3_Snapshot_10?oldid=3799210) описывают
новый синхронизируемый реестр. Его корень — **NBT-список**, не compound.
Это отдельно проверено на клиенте: compound отвергается как `Not a list`.

Три записи `axe`, `hoe`, `shovel` содержат непустые правила из нашей логики
инструментов. Топор использует существующие таблицы меди и обтёсанных блоков,
сохраняет общие свойства; лопата/мотыга учитывают воздух сверху и грань;
корнистая земля имеет отдельное правило с выпадением корней. Используются
явные имена блоков без зависимостей от отсутствующих тегов.

Схемы: [Block state provider](https://minecraft.wiki/w/Block_state_provider?oldid=3828513),
[Block state](https://minecraft.wiki/w/Custom_world_generation/block_state?oldid=3780297).
Серверные механики26.3, новые виды древесины и точное совпадение предсказания
клиента с действиями сервера требуют отдельных игровых записей. Прохождение
Configuration не доказывает эту часть. Допуск777 остаётся закрыт.

[Узоры горшков](https://minecraft.wiki/w/Decorated_pot_pattern_definition?oldid=3826756)
с26.3 также задаются динамическим реестром. Наши23черепка дают23именных
записи с `asset_id`. В список песен только для777 добавлен `bounce`
(234секунды, сигнал8 по странице Music Disc); прежние21ID не смещаются.

Первый успешный диагностический прогон получил ACK со всеми27реестрами.
До этого реальные ошибки клиента отдельно выявили отсутствующие обязательные
записи и неверный compound вместо списка. Данные записей созданы нами;
использование ресурса KnownPacks не скрывает отсутствие наших данных.

Для независимой проверки без known packs добавьте `--empty-known-packs`.
