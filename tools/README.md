# Откуда взята таблица блоков

Файлы `data/blocks.json` и `data/items.json` — списки блоков и предметов игры
для версии 26.1 (наш протокол 775). Взяты из открытого проекта
**PrismarineJS/minecraft-data**:

    https://github.com/PrismarineJS/minecraft-data/tree/master/data/pc/26.1

Скачаны командами:

    curl -o data/blocks.json https://raw.githubusercontent.com/PrismarineJS/minecraft-data/master/data/pc/26.1/blocks.json
    curl -o data/items.json  https://raw.githubusercontent.com/PrismarineJS/minecraft-data/master/data/pc/26.1/items.json

Из `blocks.json` берутся не только номера состояний, но и два списка для
выживания: что выпадает из сломанного блока (`drops`) и каким инструментом
его надо ломать, чтобы что-то выпало (`harvestTools`). Из `items.json` —
размер стопки (`stackSize`).

Для освещения из `blocks.json` берутся `emitLight` (сколько блок светит) и
`filterLight` (сколько гасит проходящего света). Оба числа в данных — на весь
блок, без оглядки на состояние, поэтому там, где свет зависит от состояния
(горящая печь, лампа, ягоды пещерной лозы, свечи по числу, огурцы в воде,
заряды якоря, хранилище и испытательный спавнер), значения выписаны
в `make_block_table.py` по страницам вики (Light и страницы самих блоков).
Там же по списку со страницы Light — какие грани у плит, ступеней, грядки,
тропинки и снега закрыты для света целиком.

## Что в них важно понимать

Эти данные — не документация. Их собрали, разобрав файлы самой игры, и выложили
как открытый набор. В описании проекта заявлена лицензия MIT, но файла с
лицензией в проекте нет, так что юридически это скорее «лежит и никому не
мешает», чем «официально разрешено». Решение брать их — осознанное.

Но по характеру это таблица чисел, а не код игры: без согласия с клиентом
в нумерации блоков ни один сторонний сервер не может работать вообще.
Кода Minecraft здесь нет ни строчки.

Версия в проекте — 26.1, у нас 26.1.2. Это соседние выпуски одной линейки,
и 26.1.2 — выпуск с исправлениями, новых блоков в нём обычно не появляется.
Совпадение проверяется в игре: если поставленный блок выглядит правильно,
нумерация наша.

## Откуда взят список видов урона

Файл `data/damage_types.txt` — список видов урона для реестра
`minecraft:damage_type`. Взят со страницы **Damage type** википедии
(minecraft.wiki), раздел «List of damage types»:

    https://minecraft.wiki/w/Damage_type

Скачан командой (выдаёт вики-разметку страницы):

    curl -A "minecraft-rust-server/0.1 (research)" \
      "https://minecraft.wiki/api.php?action=parse&page=Damage_type&prop=wikitext&format=json&formatversion=2"

Из разметки выписаны только имена видов урона — по одному в строке, по
алфавиту. Ничего, кроме имён, в файле нет: остальное содержимое записей
(messages, scaling, exhaustion) сервер задаёт сам.

Список обязан быть полным, и вот почему. Реестр целиком присылает сервер,
и этим он заменяет клиентский: чего в списке нет, того для клиента не
существует. Клиент ищет некоторые виды урона по имени прямо в своём коде —
и если не находит, падает. Именно так игра вылетала при ударе по блоку:
в списке не было `player_attack`. Поэтому совпадение списка в коде с этим
файлом проверяется тестом.

Текст страницы википедии — не игровые файлы, а её собственное описание,
и распространяется под свободной лицензией.

## Как получить таблицы в коде

    python3 tools/make_block_table.py

Программа соединяет оба списка по имени и переписывает `src/blocks_table.rs`.
Рядом с каждым числом остаётся имя блока, чтобы таблицу можно было читать
глазами. Кроме пар «предмет — блок» она собирает ещё две таблицы: блоки,
состояние которых зависит от того, как игрок их поставил, и предметы,
которыми в творческом режиме блоки не ломаются.

## Как устроен номер состояния блока

Номер состояния — не одно число, а несколько свойств, упакованных в одно
число: бревно отличается от бревна осью (x, y или z), ступень — поворотом,
половиной и формой. Упакованы они так:

* свойства идут по порядку, и **последнее меняется быстрее всех**;
* у признаков «да/нет» **первым идёт «да»** — в исходных данных списка
  значений у них нет вовсе, порядок взят из игры;
* номер = `minStateId` плюс сумма «множитель × место значения в списке».

Порядок значений берётся из данных как есть, и он неочевидный: у поворота это
north, south, west, east — ни по алфавиту, ни по кругу. Проверяется соглашение
по умолчаниям: если разложить `defaultState − minStateId` по свойствам, должны
получиться те значения, которые игра ставит сама (у бревна — ось y, у плиты —
нижняя половина, у калитки — не открыта и не в стене). Сходится — значит
и счёт, и чтение верные.

## Откуда взяты правила установки

Правила, по которым блок поворачивается при установке, взяты с википедии
(minecraft.wiki) — страницы Log, Basalt, Stairs, Slab, Fence Gate. Общего
правила нет: ступени смотрят туда же, куда и игрок, а печь или сундук —
наоборот, поэтому каждое семейство блоков считается по-своему. Что именно
выяснено и что ещё нет — написано в `src/placing.rs`.

## Откуда взята проводимость

Проводимость — своё свойство блока, и по внешнему виду оно не угадывается:
светокамень, блок редстоуна, наблюдатель и поршень — полные непрозрачные
кубы, но сигнал не проводят, а слизь, корни мангра и барьер — проводят,
хотя на полный куб не похожи. Поэтому в сборщике таблицы за основу взят
полный непрозрачный куб, а поверх лежат два именных списка со страницы
Conductivity на minecraft.wiki: «List of conductive blocks» и «List of
non-conductive blocks». Отдельно разобрана плита: двойная проводит,
обычная — нет.

## Таблицы для Bedrock

    python3 tools/make_bedrock_tables.py

Источники — только данные: minecraft-data (`data/bedrock/1.26.10`:
`blockStates.json`, `items.json`, `blocks.json`; `data/bedrock/1.26.0`:
`blocksJ2B.json`), наши `tools/data/blocks.json` и `items.json` и страница
вики «Biome/ID». Файлы minecraft-data лежат в
`~/.cache/mcsheriffanya/minecraft-data/bedrock/<версия>/` — их берут из
репозитория PrismarineJS/minecraft-data. Программа пишет в `src/bedrock/`:
перевод состояний блоков Java → Bedrock, тело пакета Item Registry,
творческий инвентарь (предметы Java, которые есть у Bedrock), перевод
предметов Bedrock → Java и номера и имена биомов (`tables.rs`).

Проверки Bedrock — роботом-клиентом bedrock-protocol как чёрным ящиком
(его код не читаем): `tools/measure/bedrockbot.js` — вход, пакеты, чанки;
`tools/measure/bedrockbuild.js` — ломание и постановка блоков
(`node … <порт> <ник>`); `tools/measure/bedrockinv.js` — инвентарь:
предмет из творческого меню, выброс. Робот
ставится в `~/node_modules` (`npm install bedrock-protocol --allow-git=all`)
и работает с `raknetBackend: 'jsp-raknet'`.
