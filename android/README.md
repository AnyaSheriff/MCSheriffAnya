# MCSheriffAnya для Android — предварительная версия

Самостоятельное приложение для запуска нашего сервера без Termux и установленной
Java. Минимум Android 7.0 (API24), целевой Android API35. Проверено в эмуляторах
Android7/API24 и Android16/API36. Есть ручной отзыв о запуске первого preview на
физическом ARM64-телефоне; это не независимый замер текущей сборки.
Ядро Java26.3 включено в APK: первый запуск работает без скачивания.

Две сборки для телефонов:

| ABI | Устройство | WebAssembly-плагины |
|---|---|---|
| armeabi-v7a | 32-битный ARMv7 | Отключены (`--no-default-features`) |
| arm64-v8a | 64-битный ARMv8/aarch64 | Включены (обычные возможности ядра) |

Отдельный x86_64 APK без плагинов нужен только для эмулятора и не является
проверкой выполнения ARM32/ARM64 на телефоне. Поддержка ABI при сборке не
означает испытание на каждом устройстве.

## Обновления ядра без переустановки APK (0.2.2-preview)

Один раз установи новый APK поверх прежнего приложения, **не удаляя приложение**.
Затем открой **Настройки → Обновления ядра → Проверить обновления**.
Останови сервер, нажми **Скачать и обновить ядро** и подтверди действие.
Приложение загрузит файл для своей архитектуры, проверит подпись и целостность,
создаст резервную копию данных и выберет новое ядро. Запусти сервер снова.
Автоматического отключения игроков или установки в фоне без подтверждения нет.

Мир и конфиги остаются в приложении. Кнопка **Вернуть предыдущее ядро** меняет
версию программы, предварительно сохранив текущие данные. Она не восстанавливает
старый мир автоматически: для этого отдельно выбери нужный ZIP в резервных копиях.
Если обновлённый файл повреждён или не дошёл до готовности при первом запуске,
следующий запуск использует прежнюю проверенную версию либо встроенное ядро.

Обновление самого интерфейса и загрузчика всё ещё требует установки нового APK.
Первые r1/r2 — две полные сборки одного игрового исходника: r2 проверяет механизм
обновления, а не добавляет игровой контент. Это предварительный канал.

Подробности для сопровождения: [core-updates.md](core-updates.md).

Основания: [Material Components1.12.0](https://github.com/material-components/material-components-android/releases/tag/1.12.0),
[DayNight](https://developer.android.com/develop/ui/views/theming/darktheme),
[динамические цвета Android](https://developer.android.com/develop/ui/views/theming/dynamic-colors).

## Интерфейс

- Сервер: действительный статус готовности, запуск, сохранение и остановка,
  адрес этого телефона и адрес локальной сети с копированием.
- Консоль: вывод ядра, команды, цвет уровней ошибок; последние64КиБ в интерфейсе.
  Полные журналы ядро сохраняет в своей папке `logs`.
- Настройки: оформление, сервер, мир, вход, производительность, сеть и дополнительные параметры.
  Основные параметры представлены полями, переключателями и списками с пояснениями.
  Проверяются числовые диапазоны, устаревшее состояние редактора и переносы строк.
  Комментарии и неизвестные строки файлов сохраняются, дубликаты изменяемого ключа
  обновляются вместе. Служебные `java-version=26.3` и `console-colors=never`
задаёт приложение; уровни ошибок окрашивает интерфейс. Запись запрещена во время работы сервера; сид существующего
  мира менять нельзя. При отказе записи второго файла первый восстанавливается.
  Несохранённый ввод сохраняется при пересоздании экрана; выход требует выбора.

Настройки ядра применяются после перезапуска; оформление — сразу. Для телефона начальные дальности обзора
и симуляции6/4, максимум10игроков. Основная версия только26.3; состояние
реализации игрового процесса и Bedrock такое же, как у включённого ядра.
Приложение не превращает частичную Bedrock-поддержку в полную.

Анонимные отчёты об ошибках по умолчанию включены, это видно на главной;
переключатель находится в «Дополнительно». Сервер стартует только по действию
пользователя. При работе используется foregroundservice с уведомлением и кнопкой
остановки, частичный wake lock; закрытие экрана приложения не является командой
stop. Автозапуска при загрузке телефона и скрытого перезапуска после принудительной
остановки нет. Сохранение мира выполняет само ядро через обычную команду `stop`.

Данные хранятся в приватной папке приложения `files/server`: config, world, logs
и auth.db. Они сохраняются при штатной остановке и обновлении APK с той же подписью.
Удаление приложения/очистка его данных удалит эти файлы. В «Настройки → Резервные копии» можно создать внутренний ZIP, сохранить его
через системный выбор файла в память телефона и импортировать обратно. Копия
включает всю папку сервера: мир, конфиги, плагины/модули, скины, логи и БД
учётных записей; бинарник ядра и оформление приложения находятся отдельно.
Внутренние копии тоже удаляются при удалении приложения, экспортированные ZIP
остаются в выбранном пользователем хранилище.

Сервер должен быть остановлен: запуск и запись конфигов на время операции
блокируются. Для копирования используется отдельная foregroundservice; смена
темы или закрытие экрана не является отменой. Перед восстановлением приложение
проверяет формат/CRC/пути/конфиги/версию, распаковывает во временную папку и
создаёт отдельный ZIP прежних данных, даже если текущий мир повреждён. Такая
автокопия сохраняет исходные байты для восстановления/разбора и сама может
содержать повреждения. Затем папки заменяются через rename.
Незавершённый импорт отмечается на диске: после перезапуска приложения прежняя
папка возвращается до открытия настроек/запуска ядра; объёмную уборку выполняет
worker. Это не гарантия сохранности при повреждении накопителя или внезапной
потере питания во время записи.

Поддерживаются собственные однодисковые ZIP формата1 для Java26.3, без ZIP64,
комментария ZIP и символических ссылок. Пределы:2ГиБ архив,4ГиБ распакованных
данных,1ГиБ отдельный файл,50000путей. Повторяющиеся пути, выход из папки,
неполный каталог, неверный CRC/формат и превышение размеров отклоняются до
замены мира. Разрешение на доступ ко всей памяти телефона не требуется:
используются ACTION_CREATE_DOCUMENT/ACTION_OPEN_DOCUMENT и выбранные URI.
Файл ZIP содержит серверные учётные записи и данные, а не только блоки мира.
В старом системном файловом менеджере Android7 ZIP может открыться как папка:
удерживайте архив, затем выберите «Открыть» в верхнем меню.
Android/OEM может принудительно завершить процесс; долгую работу с выключенным
экраном на реальном телефоне нужно проверять отдельно. Wi-Fi адрес не является
публичным адресом из интернета.

## Статистика на главной

Главная показывает онлайн/лимит игроков, TPS, время такта (MSPT), CPU и RSS
процесса ядра, доступную RAM телефона и место на накопителе. CPU усредняется
по всем доступным ядру логическим процессорам:100% означает всю эту мощность.
RSS — оценка ОС физической памяти процесса, не размер Rust-кучи. Если ОС не
разрешает прочитать показатель, отображается прочерк. Первая CPU-оценка появляется
после двух снимков; после перезапуска отсчёт начинается заново.

Обновление примерно раз в2секунды, только пока видна главная. Снимки старше
6,5секунды скрываются. Пустой мир в режиме сна обозначается «Пауза»;
чтение статистики не выполняет команды и не возобновляет тики. Встроенная
иконка — логотип проекта; на совместимом Android13+ есть монохромная версия
для системных тематических значков.

### API приложения и ядра

API включается только при наличии переменных `MCSA_APP_API_SOCKET` (путь) и
`MCSA_APP_API_SESSION` (идентификатор запуска из ASCII-букв/цифр/дефиса,
1–64символа). Приложение создаёт новый идентификатор на каждый запуск и
использует Unix-сокет `files/mcsa-api.sock` в своей приватной папке. Обычный
сервер без этих переменных не создаёт API. TCP/UDP-порт не открывается.
Права сокета0600; перед новым запуском приложение убирает только свой старый
сокет после завершения прежнего процесса. Ядро произвольные старые пути не удаляет.

Клиент отправляет ровно `status\n`, получает одну строку JSON и EOF. Версия1:

```json
{"version":1,"session":"<идентификатор запуска>","pid":123,"uptime_ms":2500,
 "online":0,"max_players":10,"tps":20.0,"mspt":0.8,"paused":false,
 "frozen":false,"tick":50,"cpu_time_us":100000,"logical_cpus":4,
 "rss_bytes":67108864}
```

CPU-время — сумма пользовательского и системного времени всех потоков процесса
через `getrusage(RUSAGE_SELF)`; RSS читается только из `/proc/self/statm`.
`tps`/`mspt`/`frozen` могут быть `null`, если снимок занят; ресурсные поля могут
быть `null`, если ОС их не предоставляет. Во сне `paused=true`, TPS/MSPT=0.
Это только чтение: команд, модификации файлов и загрузки кода через API нет.
Не больше4одновременных запросов; запрос ограничен1секундой. Приложение
проверяет версию и идентификатор запуска, ограничивает ответ8КиБ.
Системные RAM/диск берутся Android API, а не из вывода консоли.

## Сборка

`tools/android/build-core-native.sh` и workflow `android-core-native.yml`
последовательно собирают загрузчик и полное shared-ядро для ARMv7, ARM64 и тестового
x86_64 через NDK с API24 и выравниванием16КиБ. Host — ELF PIE с системным Bionic
загрузчиком; ядро — ET_DYN без PT_INTERP, с тремя экспортами ABI1.
Для проверки OTA создаются две разные полные сборки, r1/r2 в первом архиве.
Сохраняются точные SHA256/NDK/lock/исходный и производный manifest/логи.
Сам native workflow не публикует файлы, теги или Docker.

`runtime-pin.json` закрепляет успешный run/source/artifact и SHA каждого host/core.
Для отдельного обновления ядра новый проверенный pin можно хранить в `ota-pins/`,
сохранив `runtime-pin.json` и уже выпущенный APK. Подпись через
`sign-core-update.py --pin PATH` использует выбранный pin; приватный ключ остаётся
на компьютере выпуска. Workflow APK принимает `core_update_pin` и подписанный
`test_manifest_url`: тест устанавливает ядро другой ревизии/исходников поверх
существующего встроенного ядра. Это не требует изменения пользовательского APK.

В свежей копии репозитория с авторизованным gh:

```sh
python3 tools/android/fetch-runtime.py
cd android
./gradlew -PapkAbi=arm64-v8a :app:clean :app:assembleDebug
# Скопировать готовый APK до следующего clean.
./gradlew -PapkAbi=armeabi-v7a :app:clean :app:assembleDebug
```

Нужны JDK17 и AndroidSDK35. Gradle8.11.1 закреплён с SHA256 официального архива,
AGP8.9.2. `preBuild` сверяет каждый включаемый бинарник с pin по SHA256 и размеру.
`verify-apk.py` проверяет именно наш APK и тождество включённых байтов runtime;
apksigner/zipalign отдельно проверяют подпись и упаковку. В APK включены
`lib/<ABI>/libmcsa.so` (host) и `lib/<ABI>/libmcsa_core.so` (встроенное ядро).
Android извлекает их в read-only nativeLibraryDir. ProcessBuilder запускает host
без shell и JNI. Host выбирает проверенное встроенное или отдельно обновлённое
shared-ядро; скачанный файл не запускается через execve. Конфиги и мир отдельно.

Сейчас это debug APK для испытаний. Локальная debug-подпись сохраняет возможность
обновления локальными сборками с тем же ключом. Ключ CI временный, поэтому
CI APK не следует использовать для постоянного мира или считать production-релизом.
Постоянная подпись релиза и публикация требуют отдельной подготовки; приватные
ключи не включаются в репозиторий или артефакты.
