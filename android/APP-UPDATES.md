# Обновление приложения Android

После одной установки APK с этой функцией: Настройки → Обновления → Приложение Android → Проверить → Скачать → Установить. Это отдельная операция от обновления ядра. Установку подтверждает системный установщик Android. На Android 8+ первый раз потребуется разрешить установку из MCSheriffAnya, вернуться и нажать установку снова.

Установка доступна только при остановленном сервере и завершённых операциях. С захвата APK до окончательного результата Android удерживается общая блокировка запуска сервера, резервных копий, обновления ядра и замены скачанного APK. Автоматической остановки/отключения игроков нет. Мир и настройки остаются в данных приложения; важную копию можно заранее экспортировать через раздел резервных копий. Не удаляйте приложение перед обновлением: удаление стирает его данные.

Канал: `https://raw.githubusercontent.com/AnyaSheriff/MCSheriffAnya/android-updates/app-preview.json`.

```json
{
  "format": 1,
  "package": "ru.sheriffanya.mcsa",
  "version_code": 6,
  "version_name": "0.2.4-preview",
  "apks": {
    "arm64-v8a": {
      "bytes": 12345678,
      "sha256": "<64 lowercase hex characters>",
      "url": "https://github.com/AnyaSheriff/MCSheriffAnya/releases/download/<immutable-tag>/<immutable-name>.apk"
    }
  }
}
```

Для публикации нужны отдельные записи `arm64-v8a`, `armeabi-v7a`, `x86_64`. Код версии строго растёт. APK должен иметь тот же package и точный набор текущих сертификатов установленного приложения. Смена ключа/переход на другой подписант не поддерживаются. Публикация APK с временным ключом CI недопустима.

Описание ограничено 64 КиБ, APK — 256 МиБ. Начальный адрес APK ограничен release-путём проекта; каждое перенаправление допускает только HTTPS и точные GitHub-хосты. Используются обычная проверка TLS и существующие публичные CA для GitHub на Android 7; ослабления TLS нет. Перед предложением установки и повторно перед передачей Android проверяются размер/SHA, пакет, код/имя версии, подписанный manifest metadata `ru.sheriffanya.mcsa.RUNTIME_ABI`, сертификаты через PackageManager (API 24 и API 28+). Metadata архитектуры связывается с выбранным каналом; фактическую совместимость native libraries окончательно проверяет Android. Телефон не разбирает ELF/APK ZIP.

Загрузка идёт в отдельный cache-каталог. Предыдущий проверенный APK сохраняется при ошибках сети/проверки нового файла и восстанавливается после перезапуска процесса без сети. Кэш Android может очистить самостоятельно. При убийстве процесса незавершённая загрузка не становится установочным кандидатом; её нужно повторить. Это загрузка по запросу, без фонового расписания и без гарантии продолжения после закрытия приложения. После повторной проверки полный APK копируется без распаковки в одну системную PackageInstaller.Session; во время копирования повторно проверяется SHA. Кэш недоступен внешним приложениям.

Сам канал не подписан отдельным OTA-ключом: окончательная авторизация APK — точное совпадение подписи уже установленного приложения плюс системная проверка Android. Старая/равная версия отвергается независимо от содержимого канала. Обновление ядра сохраняет прежнюю отдельную криптографическую схему.

Ожидание установки и id сессии сохраняются до commit. После гибели процесса блокировка восстанавливается до старта служб; новая установленная версия или отсутствие системной сессии снимает её. Отмена через приложение сначала уничтожает сессию; если Android ещё завершает установку, блокировка остаётся до результата. Возврат в приложение сам по себе не считается отменой. Единственный неэкспортируемый receiver принимает явный PendingIntent конкретной сессии; для API 31+ используется mutable PendingIntent с явными компонентом/пакетом, для API 31+ также явно требуется действие пользователя. Подтверждение Android открывает только находящаяся на экране Activity. При утрате экрана подтверждения после перезапуска можно отменить сохранённую сессию и повторить установку.

Тесты: обычный JUnit проверяет адреса и политику подписантов; Android instrumentation проверяет описание и реальные сертификаты установленного APK через PackageManager против сертификата системного пакета. AppInstallReservationTest проверяет реальную общую блокировку, запрет замены APK, отмену/ошибки, восстановление маркера и настоящую запись собственного APK через PackageInstaller.Session с уничтожением без commit. API36 дополнительно проверяет полный readback SHA; на API24 SELinux запрещает передачу читаемого FD для apk_tmp_file приложению (raw CI43712684923), поэтому там проверяются имена/размер системной сессии и проверенный при записи SHA, а фактическая установка/подпись проверяется отдельным системным flow. Различие явно записывается в app-install-session-stage.json. Нужен CI fixture appUpgradeApk. Реальная установка новой версии, системные экраны разрешения и работа на физическом ARM-телефоне требуют отдельной проверки; наличие тестового кода не означает их прохождение.
