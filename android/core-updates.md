# Отдельные обновления Android-ядра

Минимум Android7/API24, target35. Приложение code4+ содержит маленький PIE host
`libmcsa.so` и полное встроенное ядро `libmcsa_core.so`. Host запускается из
`nativeLibraryDir` отдельным процессом с прежними cwd/stdin/stdout. Он использует
публичные `dlopen`/`dlsym` и ABI1: `mcsa_core_api_v1`, `mcsa_core_main_v1`,
`mcsa_core_build_id_v1`. Нет JNI в UI-процессе, скачанного execve или понижения target.

Обычный desktop Rust entry не меняется: cdylib собирается только с `android-core`
и производным manifest в отдельной копии исходников. API24 Bionic/16K ELF:
ARMv7 и x86 без WASM, ARM64 с обычными плагинами.

## Доверие и переключение

- Корневой открытый P256 ключ встроен в APK. Приватный ключ хранится только на ПК
  сопровождающей; в Git, CI и VPS его нет. Подпись ECDSA/SHA256 над исходными байтами
  payload проверяется до чтения полей. Изменение доверенного ключа требует APK.
- HTTPS применяется к метаданным, файлам и перенаправлениям; штатная проверка TLS.
  Описание до64КиБ, payload до32КиБ, модуль до128МиБ, до5перенаправлений.
  Проверяются версия схемы, игра26.3, data_compat1, hostAPI1, min_app, ABI,
  положительная ревизия, buildID/source, размер и SHA256. Старые ревизии не ставятся
  через обычную загрузку; ручной возврат предыдущего слота разрешён.
- Файл создаётся read-only до записи через уже открытый дескриптор; fsync, проверка
  SHA/ELF, переименование временной папки. Метаданные сохраняются вместе с подписью.
  Перед каждым запуском повторно проверяются подпись, SHA, ABI и права файла.
- Смена ядра доступна только после остановки и завершения дочернего процесса.
  Глобальная операция исключает одновременный запуск, настройку и импорт мира.
  Перед активацией создаётся обычный ZIP данных сервера. Указатели active/previous
  и состояние первого запуска сохраняются через AtomicFile.
- Первый запуск подтверждается реальной строкой готовности и buildID загрузчика.
  Ошибка до готовности или прерванная попытка возвращает previous/bundled для
  следующего запуска. Пользовательская остановка не считается неудачной установкой.
  Автоматически содержимое мира не откатывается: сохранённый ZIP можно импортировать.

Это защита от повреждённой загрузки и подмены без ключа подписи. Она не обещает
защиту от root или произвольного кода с UID самого приложения. Совместимость данных
data_compat1 — обязательство сопровождающей проверять изменения формата до публикации.

## Публикация

1. Собрать собственный native workflow и независимо проверить source, успешный run,
   artifact digest, receipt, все ELF/SHA/ABI/API. Закрепить результат в runtime-pin.json.
2. Локально выполнить `python3 tools/android/sign-core-update.py NATIVE OUTPUT --notes '…'`.
   Скрипт использует отдельный локальный ключ через OpenSSL, не читая его в Python
   и не копируя. Он проверяет соответствие открытого ключа и каждого файла пину.
3. Загрузить уникальные неизменяемые `.so` assets в релиз. Не использовать clobber.
   Снова скачать по публичным HTTPS адресам и сверить каждый размер/SHA.
4. Только после этого опубликовать подписанный preview.json в отдельной ветке
   `android-updates`. URL канала фиксирован в BuildConfig; он не заменяет доверенный ключ.
   Закрытый ключ не передаётся GitHub. Записи о source/run/SHA сохранить в журнале.
5. Прогнать реальную установку/обновление на API24/36, мир/config/status777/backup/
   возврат/подмена/отказы. Эмулятор x86 не заменяет физический ARM и долгий Doze.

Локальный APK подписывается прежним стабильным ключом приложения. Эфемерные
CI APK нужны для эмуляторов, ими нельзя заменять пользовательскую установку.

Официальное ограничение Android10 на execve файлов в writable app home:
[behavior changes](https://developer.android.com/about/versions/10/behavior-changes-10).
