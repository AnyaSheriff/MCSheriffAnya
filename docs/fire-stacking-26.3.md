# Сложение «Защиты от огня», Java 26.3

Проверены шесть сочетаний на одинаковой полной алмазной броне. Атакующий
наносит один настоящий удар алмазным мечом с «Заговором огня I». Броня и меч
выдаются внутри записи, до удара: их получение проверяется по пакетам владельца
и второго наблюдателя. У обоих игроков перед опытом наблюдается 20 HP.

| Чары на броне | Наблюдаемый интервал горения, такты | Число ожогов | HP после опыта |
|---|---:|---:|---:|
| Нет | 79 | 3 | 15.110000610351562 |
| Нагрудник IV | 31 | 1 | 17.43000030517578 |
| Ботинки IV | 31 | 1 | 17.43000030517578 |
| Нагрудник IV + ботинки IV | Не поджигается | 0 | 18.110000610351562 |
| Нагрудник I + ботинки III | 31 | 1 | 17.43000030517578 |
| Все четыре части II | Не поджигается | 0 | 18.110000610351562 |

В первом сохранённом наборе эти значения совпали у оригинала и нашего ядра,
включая оба наблюдателя. После самого удара в каждом случае оставалось
18.110000610351562 HP. Все четыре предмета брони и меч теряли по единице
прочности. Отсутствие поджигания допускается только после доказанного попадания
с правильной экипировкой и потерей HP.

Длительности в таблице — округлённые интервалы между полученными флагами огня.
Это не прямое измерение внутренних счётчиков сервера. Для повторной проверки
этих интервалов допускается один такт; значения здоровья, число ожогов и наличие
поджигания сравниваются точно. Вывод относится к указанным шести сочетаниям.

Исходные сценарии и критерии закреплены до первой записи в source `4169fb07`.
`tools/blackbox/ci/fire-stacking-777.json` хранит актуальную подготовку и отдельную
`phase_revision` для следующего опыта. Эталон наблюдений оригинала находится
в `fire-stacking-original-777.json` рядом. Он получен после записи и независимого
разбора, а не выведен из нашей формулы сложения чар.

Первая запись: source `4169fb07d8f8362471fd22eeae37722dea012b1b`,
CI `42964539676`, artifact `13830852852`, ZIP SHA256
`232b1c65fac7bb99e1eb6166458abd12271b92cad9c4c1b7637dd7a66ead83c6`.
Этот CI завершился **FAILURE**: новый анализатор ошибочно передал метаданные
постороннего предмета в строгий декодер игрока. Все 12 записей завершились;
исправленный фильтр цели проверен на тех же сырых пакетах независимо
(5450 проверок). Первоначальные неуспешные результаты сохранены.

Игровой код в этой работе не менялся: использован проверенный runtime source
`aacb8742e6e50bd2687ddfd16bee708aa3d2b9ab`, build CI `42878839567`,
SHA256 `edd3b9105ad72bcdda6a46609e51e45518bf8ae7e93fe6f0ae347f74d08d210c`.
Отдельный адаптер сверяет настоящий receipt сборки, ELF, lock и 830 входных
файлов компиляции. Чужие исходники и содержимое оригинального JAR не читаются.

Общее сравнение пакетов первого набора остаётся `mismatch-open`: в каждом
случае два сдвига рассылки атрибутов атакующего на 1–2 такта. Пропущенных и
лишних событий, ошибок декодирования и предупреждений нет. Старые маски не
расширялись. Совпадение показателей огня не означает полного паритета пакетов,
боёвки или всего игрового процесса.

Чистые проверки без запуска серверов:

```sh
python3 -B -m unittest discover -s tools/blackbox -p 'test_fire_stacking*.py' -v
```

Долгие парные записи выполняются отдельным GitHub workflow
`fire-stacking-checks.yml`; локальный сервер и опубликованные сборки не меняются.

## Фаза рассылки атрибутов

В 12 записях второго набора перед стартом не оказалось измеренных пакетов
скорости атаки. Ограничения фазы были пустыми; `verified=true` лишь подтверждало
отсутствие нарушенных ограничений. Этого недостаточно для вывода о причине
сдвигов рассылки между серверами.

Следующий опыт сохраняет все шесть сочетаний брони и прежние эталоны HP/огня.
Перед калибровкой атакующему временно выдаётся деревянный меч, затем он снимается.
Настоящий пакет скорости атаки определяет фазу. До записи снова остаётся пустая
рука; исходная команда выдачи свежего алмазного меча на такте 0 сохранена.
Удар остаётся на такте 20. Само изменение подготовки ещё не доказывает,
что найденная причина полностью объясняет прошлые сдвиги.
Оба клиента по-прежнему должны получить реальную экипировку до этого удара.

Регистратор дополнительно сохраняет payload каждого измеренного пакета и то же
время, что попало в список отсчётов. Новая проверка требует непустое ограничение
`player_attributes`, настоящий пакет до старта, согласованную чётность с часами
и точную ссылку на исходную запись оригинала. После старта отсчёты связываются
с реальными пакетами в журнале клиента. Без этих доказательств опыт не пройдёт
проверку подготовки. Записи, полученные раньше, сохраняются в прежней области
доказательств; сдвиги остаются открытыми до нового результата. Сравнение пакетов
и его маски не меняются.

## Результат калиброванного прогона

CI `42971286751`, source `bbaf2845c765c10b5644c48754a5a63de10ae3ed`, завершился
успешно. Все шесть сравнений прошли прежним компаратором: суммарно
`206 / 0 / 0 / 0` (совпало / сдвинуто / отсутствует / лишнее), без ошибок
декодирования и предупреждений. Прежние маски сохранены.

В каждой из 12 записей получены два настоящих пакета скорости атаки до старта
и пакет после удара. Проверены payload, владелец, совпадение времени с отсчётом,
чётность относительно часов и ссылка на файл оригинала. Прежние эталоны
здоровья, числа ожогов, наличия и длительности горения также прошли проверку
внутри этого CI. Износ всех четырёх предметов брони и меча остался равен единице.

Artifact `13833896247`, 6484069 байт, ZIP SHA256
`36fabd5c09ded5d6906d67b8ce9f0a48f6cf8b6aba7db79d8b4881e8987561af`.
Результат относится к этим шести подготовленным опытам. Подготовка до записи

сдвигов. Игровой код и сравнение пакетов в этой работе не менялись.
