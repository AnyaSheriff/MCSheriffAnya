# Собственная совместимость Java 1.12.2–26.3

Решение владелицы 18 октября 2026: «нам надо полноценные аналоги ViaVersion и
ViaBackwards». Затем уточнила: «продолжает делать до 1.12.2 покачто». Текущая нижняя
граница — 1.12.2; версии 1.8–1.11 пока отложены.
Это самостоятельный переводчик на Rust внутри MCSheriffAnya; реализации
ViaVersion/ViaBackwards и другие чужие серверы/прокси не используются.
Полный перенос игровых механик26.3— отдельная обязательная часть:
[список контента и критерии](java-26.3-content.md).

## Что должно работать

- Новый клиент подключается к серверу со старой основной версией.
- Старый клиент подключается к серверу с новой основной версией.
- Игроки разных поддержанных версий одновременно видят один серверный мир.
- Вход, AuthMe/online-mode, мир/свет/измерения, чат/команды, инвентарь/крафт,
  сущности/эффекты, взаимодействия/PvP, смерть/respawn и повторный вход проверены.
- Отсутствующие объекты имеют явную проверенную визуальную замену; настоящие
  предметы и серверные действия при этом не превращаются в заменители.
- У каждого направления и версии есть отдельный статус и записи проверок.

Версия игрового поведения принадлежит серверу. Подключение клиента 1.12.2 само
по себе не превращает бой, рецепты и генерацию современного сервера в 1.12.2.
Совместимость отображения и действий проверяется отдельно от эмуляции старых
игровых правил. Снапшоты и модифицированные протоколы в первый диапазон не входят.

## Приоритет клиентских версий

Уточнение владелицы 19 октября 2026: сначала полностью проверить популярные
клиенты **1.12.2, 1.16.5, 1.17, 1.20.1, 1.21.1 и 1.21.11**, затем остальные
релизы диапазона до26.3. Это приоритет первой группы, а не сокращение общей
цели. Версия1.17 указана буквально; готовность1.17.1 отдельно не подразумевается.
Переход основной версии ядра на26.3 остаётся обязательным.

20 октября Аня уточнила: «26.2 нужна была в аналоге ViaVersion».
26.2 входит в приоритет как версия подключаемого клиента. Отдельный основной
профиль26.2 не требуется; цель основного перехода —26.3.
Для каждого приоритетного клиента действуют все условия включения версии ниже.
Нужные внутренние переходы можно добавлять по мере работы, но незавершённые
промежуточные клиенты не получают публичный допуск автоматически.

Для этих точных версий закреплены номера протоколов 340, 754, 755, 763, 767,
774,776 и воспроизводимая [инвентаризация JSON-схем](../tools/research/priority-protocol-layouts.md).
Это исходные данные для работы, не готовые клиентские маршруты. Например,
1.17 уже передаёт изменённые слоты щелчка, но ещё не имеет `stateId`; заменить
его форматом 1.17.1 нельзя.

## Архитектура и порядок

Существующий `mcsa-protocol` сохраняется общей библиотекой. Внутренние ID мира
не зависят от клиента. Каждый переход разбирает входной формат, меняет нужные
поля и ID, затем кодирует целевой формат. Число версий не должно приводить к
отдельной реализации каждой пары: проверенные соседние переходы образуют цепочку.
Готовность цепочки определяется самым слабым переходом, а не известным номером
Handshake. Обратное направление не считается готовым автоматически.

| Этап | Работы | Статус |
|---|---|---|
| 26.1.2 ↔ 26.3 | Полный игровой вход, весь обязательный сетевой обмен | 775/777 в профиле26.3, raw mixed17/17; полный паритет не заявлен |
| 26.2 | Отдельные таблицы, переходы к соседним версиям и клиентские пробы | В разработке; публичный маршрут закрыт |
| 1.20.5–1.21.x | Компоненты предметов, Configuration, новые реестры | Запланировано |
| 1.19–1.20.4 | Чат/подписи, вход, старый формат вещей | Запланировано |
| 1.17–1.18.x | Разная высота мира, чанки/свет, смещение вида для старого клиента | Запланировано |
| 1.13–1.16.x | Переходы ID/state, сущности, инвентарь, измерения | Запланировано |
| 1.12.2 | Старые числовые предметы/блоки, metadata, offhand | В разработке; допуск закрыт |
| 1.8–1.11.x | Дополнительные старые форматы и ограничения действий | Отложено по решению владелицы |

Это группы работ, не обещание поддержки всех патчей группы. Полный список
релизных протоколов будет закрепляться по разрешённым JSON и проверяться
входом каждого отличающегося протокола. Клиенты 1.12.2 и ниже сейчас не допускаются.

Уже добавлены LightData/UpdateLight, палитры и полный конверт MapChunk
с явным контекстом измерения. Перевод данных блоков пока принимает только
наблюдавшиеся типы и ограниченные схемы NBT. Добавлены ограниченные современные
слоты/пакеты инвентаря и отдельный перевод LegacySlot1.12.2 (636 точных вариантов).
[Поддержанные данные и ограничения](../tools/research/items-1.12.2-26.3.md).
Для1.12.2 работают начальный Login/Play и щелчки окна0 в маркерном тестовом
сервере. Далее нужны остальные компоненты, другие окна/транзакции1.12.2,
оставшиеся NBT-схемы блоков, сущности/частицы и остальные обязательные пакеты.
Перенос основной версии мира на 26.3 остаётся отдельным
условием: нужны и игровые механики, а не только успешный сетевой вход.

Для1.12.2 добавлен кодек чанков по семи построенным секциям официального
сервера: палитры4–8/13бит, встроенный свет, полный/частичный пакет. Снимок
мира ядра проходит проекцию в явно выбранное окно256уровней и шифрованный
транспорт в интеграционном тесте. 896состояний сопоставлены по JSON;
шесть соседских состояний травы/подзола/мицелия дополнены явной проверкой снега.
Прочие неподдержанные объекты отклоняются. Настоящий клиент340 прошёл начальную
сессию общего ядра в отдельном Xvfb. Автоматическое переключение высоты,
полные дополнительные данные и весь игровой обмен остаются незавершёнными;
публичный вход340 закрыт. [Проверки и ограничения](../tools/research/chunks-1.12.2.md).

## Инвентарь и старое представление сущностей

Все исправления игровых правил выполняются в общих обработчиках, а не в
отдельном наборе правил старого клиента.

- Официальные340/775/777 дали одинаковые12снимков обычных режимов инвентаря.
  На тестовом ядре775/777 повторены все12; после добавления выпавших вещей
  на340 прошли18проверок и все12снимков **без пропусков выбрасывания**.
  Для340 используется bedrock: получение камня пока открывает неподдержанные
  рецепты. [Представление предметов и ограничения](../tools/research/legacy-item-entities.md).
- Устранены принятие неподходящих вещей в броню, неправильный остаток курсора
  при творческом перетаскивании и отклонение отрицательной ревизии современного
  щелчка. Дополнительно записаны5общих пограничных случаев брони на340/775 и
  3случая второй руки на775; отдельные наблюдения подтверждают сохранение ACK
  после Close Window и его сброс при смерти/возрождении340.
- Повторный обмен брони и отдельный `/give` на official775 подтвердили
  пополнение существующей стопки во второй руке при полном рюкзаке.
  Исправление общего `Inventory::put` описано в
  [отдельном отчёте](../tools/research/inventory-armor-edges.md).
- Устранён путь выдачи дорогого товара по дешёвой сделке при прежней оплате.
  [Торговая проба](../tools/research/trade-selection.md) прошла на official775/777
  и testcore775/777: по6контрольных точек и12выборов, совпадают товары, оплата
  и реальные счётчики использований. Исправлены также потеря остатка оплаты
  при очистке окна торговли и потеря книги при полном инвентаре.

Наблюдения и результаты относятся к указанным в отчётах сборкам. Они не
заменяют проверки последующих изменений; результаты общего прогона
записываются отдельно.
Сетевые торговые проверки не подтверждают старые окна торговли340.

Формат playerdata v10 добавляет сохранение отдельного курсора Java/Bedrock,
включая компоненты и полный рюкзак, с чтением прежних форматов1–9.
Это отдельное изменение сохранения; его проверки не входят в приведённые
выше сетевые пробы. Старое ядро v9 не читает новый файл; автоматического
обратного преобразования нет. См. [условия отката](world-version-transitions.md#курсор-игрока-формат-playerdata-v10).

Ограниченный Cow-only adapter добавлен к представлению Item. На общем ядре
TCP-проба прошла11проверок видимости: adult/baby, здоровье, движение, атрибуты
и возврат тех же ID/UUID после ухода за дальность. Чанки оставались в памяти;
дисковая выгрузка/загрузка этим не проверялась. Настоящий клиент340 на общем
ядре прошёл10проверок/194пакета; вручную подтверждено отображение adult/baby
до и после возврата в видимость, со смещением и поворотом взрослой коровы.
Первый неинформативный запуск с падением клиента сохранён отдельно; итоговый
повтор проверяет реальный пол чанка и устойчивое положение камеры на земле.
[Стадии наблюдений и границы](../tools/research/legacy-cow-observations.md).

Остаются старые контейнеры, полная книга рецептов, полное представление вещей
и остальных сущностей, старый AuthMe, смена окна высоты, остальные клиентские
маршруты и полный игровой контент26.3. Отдельно остаются риски сохранений:
playerdata и мир не образуют общей транзакции, выпавшие вещи не сохраняются.
Исправления обычных щелчков не являются гарантией отсутствия дюпов при сбое.
Публичный допуск по-прежнему только775; основной игровой профиль26.3 не включён.

## Замены для старого клиента

Политика замены должна задаваться по имени/свойствам объекта, не по случайному
числовому ID. Для блоков отдельно проверяются форма/коллизии и взаимодействие;
для сущностей — вид, размер, пассажиры и атаки; для вещей — видимый стек и
неизменяемая серверная идентичность. Возвращённые клиентом данные сверяются с
серверным контейнером и его ревизией, чтобы подделка отображения не меняла
настоящий предмет, количество или компоненты. Замены никогда не записываются
в сохранённый мир/инвентарь как настоящие объекты.

Для775 в профиле26.3 явная таблица — `src/gameplay_catalog/client-775-views.json`:
плиты/ступени → кварцевые, стенки → каменные кирпичные, тополь → дуб, минералы → камень,
шип → капельник, соломенная кровать → белая; подушки-предметы → ковры, карты → filled_map.
Сущности: лодки → дубовые, куб серы → слизень, подушка → стойка для брони.
Свойства формы переводятся отдельно для каждого состояния; обратного распознавания по заменителю нет.
CreativeSlot775 при новых вещах возвращает авторитетный инвентарь; [проверить] графику/размеры заменителей сущностей и растений.

Для низких старых миров нужен отдельный способ представления высоты с
проверками движения/телепортации; простое обрезание координат неприемлемо.

## Изменение основной версии существующего мира

Требование владелицы 19 октября2026: «если повышают версию: аккуратно делать
генерацию новых чанков, при понижении делать бекап папки мира». Ниже план
реализации; миграция игровых профилей ещё не реализована.
Конкретное устройство хранения, блокировок, копирования и восстановления
зафиксировано в [техническом решении](world-version-transitions.md).

- **Повышение:** существующие чанки и постройки сохраняются. Новые чанки
  использовали бы генератор целевого профиля; согласование рельефа выполняется
  на новой стороне границы, без перезаписи старых построек. Размещение новых
  структур не должно менять уже существующие соседние чанки. Версия генерации
  сохраняется для чанка отдельно от текущей версии игровых правил. Согласование
  границ нужно проверять отдельно для каждой поддержанной пары генераторов.
- **Понижение:** перед любой записью обязательна полная резервная копия папки
  мира, со всеми измерениями, контейнерами, сущностями и данными игроков,
  включая инвентарь и эндер-сундуки. Копирование производится до игрового запуска,
  при остановленных писателях. Ошибка копирования/нехватка места прерывает
  миграцию; неполный бэкап не считается готовым.
- **Проверка совместимости:** конфиг задаёт желаемый профиль, а сохранение
  хранит фактический. До конвертации проверяются блоки/состояния, вещи и их
  компоненты, сущности, измерения, координаты/высота, рецепты и отложенные
  действия. Неподдержанные данные дают отчёт с местами и количеством; автоматическое
  удаление или замена воздухом не являются допустимым преобразованием.
- **Применение:** преобразование готовится в отдельной копии. Проверенный
  результат активируется целиком; журнал миграции позволяет после сбоя выбрать
  прежнее или завершённое состояние, а не смесь двух версий. Частичный перенос
  инвентаря/сундуков недопустим из-за потери или дублирования вещей. Дополнительные
  игровые данные плагинов требуют собственного проверенного перехода.
- **Версии данных:** номер раскладки файла `.mcs`/playerdata, версия реестра
  сохранённых ID, профиль игровых правил и версия сетевого клиента — разные
  значения. Числовые ID из сохранения нельзя переосмысливать новой таблицей.
  Старые сохранения без профиля требуют явного распознаваемого исходного формата;
  желаемая версия из конфига не является доказательством их происхождения.
- **Откат:** восстановление бэкапа возвращает весь снимок, включая игроков,
  к моменту его создания. Изменения после снимка не переносятся автоматически.
  Смена клиентской версии сама по себе не запускает миграцию мира: старые
  клиенты используют сетевой перевод и общее серверное состояние.

## Условие включения версии

Проверенный маршрут должен пройти не только Status/Login, но и получение мира,
смену измерений, движение/телепорт, блоки/контейнеры/крафт, отображение сущностей,
бой, смерть/повторный вход. Дополнительно проверяются вход в online/offline,
шифрование/сжатие, неверные пакеты и попытки подменить предмет через заменитель.
Для PvP сравниваются серверные результаты и уже сохранённые black-box сценарии.
До этого маршрут остаётся закрытым, даже если отдельные адаптеры работают.
