# Диагностика TNT на границах чанков

После сетевого исправления тест 8000 TNT всё ещё завершился по пределу 90 секунд:
оставались три наблюдаемых заряда. Отправленные клиенту чанки не показывают,
какие чанки сервер действительно держит в памяти. Причина этих трёх остатков
пока не доказана; прежний неудачный результат не отменён.

В текущем ядре движение предметов проверяет исходный чанк, а уменьшение запала
TNT — чанк после движения. Перелетевший в отсутствующий чанк заряд может
замереть до загрузки этого чанка. Новые тесты фиксируют существующее поведение
на положительной, отрицательной и диагональной границах, остановку на 100 тактов,
независимую работу соседнего заряда и продолжение после загрузки. Это
характеризация нашего ядра, не доказательство соответствия оригиналу.

## Включение

Только для отдельного диагностического запуска:

```sh
MCSA_TNT_DIAGNOSTICS=1 ./mcsheriffanya
```

Переменная читается один раз при запуске потока мира. Только точное значение `1`
включает сбор. По умолчанию нет дополнительных обходов сущностей, снимков или
вывода. Физика, загрузка чанков и ограничения времени не меняются.

В журнале появляются строки с префиксом `MCSA_TNT_DIAGNOSTICS`, далее JSON:

- `tick`, `dimension`: фактический такт сервера и измерение;
- `before`, `after_step`: состояние до и после движения, до уменьшения запалов;
- каждый снимок содержит `total`, `loaded`, `omitted` и до 64 записей `samples`;
  запись содержит ID, позицию, скорость, запал, координаты чанка и `loaded`;
- `sampled_fuses_after_burn`: пары ID и запала после уменьшения; `null` означает,
  что этот выбранный заряд извлечён на взрыв;
- `exploding`: число зарядов, извлечённых на взрыв в этом шаге; это ещё не
  подтверждение завершённого взрыва и не число уничтоженных блоков;
- `world_lock_wait_us`: время ожидания замка данного мира в выбранном такте;
- `item_stage_elapsed_us`: движение, промежуточный снимок, шаг опыта и запалы.
  Не включает ожидание замка предметов, начальный/конечный снимок, сам взрыв,
  запись журнала и остальные фазы такта. Это не длительность всего такта;
- `budget_exhausted`: последний разрешённый снимок данного измерения.

Снимается один шаг каждые 20 тактов, только при наличии TNT, не более 120
снимков на каждое из трёх измерений. Пустой снимок бюджет не расходует.
Счётчики относятся только к выбранному шагу, **не ко всему интервалу**.
Подробности ограничены первыми 64 TNT в порядке хранения; остальные входят
в общие количества и `omitted`. Отсутствие ID в выборке не означает его удаление.
После исчерпания бюджета отсутствие строк также не доказывает отсутствие TNT.

Снимки собираются под уже имеющимися замками, JSON и вывод выполняются после
их освобождения. Очередь в пределах такта содержит не более трёх снимков;
новых потоков и файлов нет. Диагностика добавляет работу и может влиять на
измеряемое время: сравнивать её скорость с обычным запуском как чистую
оптимизацию нельзя.

## Следующая проверка

Сначала малый изолированный опыт с загруженным и отсутствующим чанком, затем
при необходимости повтор большого теста с прежними пределами. Сопоставлять
позиции и запалы по ID и серверному такту. Изменение `loaded` между снимками
показывает состояние в точках наблюдения; полного журнала загрузок/выгрузок нет.
Сравнительная проба с оригиналом нужна до изменения правил загрузки или физики.
Ни готовность 8000/20000 TNT, ни полная миграция 26.3 этим пакетом не заявляются.
