# Поворот мобов командой /tp

Собственные обычные команды на официальном Java26.1.2 (775),29 случаев:
`tools/protocol-bridge/testdata/mob-teleport-observations.json`.
JAR только запускался в отдельном временном мире, исходники не исследовались.
Два запуска (25+4) завершились exit0; SHA256 результатов и журналов в fixture.

Наблюдения: оба угла приводятся к[-180,180), затем pitch ограничивается±90.
Именно +270→-90,-270→90 и±360→0 отличают это от простого ограничения.
Yaw180→-180,±450→±90; pitch±95 и±450→±90. Указанный yaw меняет и голову.

Относительные углы используют направление контекста команды: console0/0,
player35/-12. Поэтому `~10 ~5` даёт10/5 и45/-7 соответственно.
`execute as` не меняет направление контекста, `execute at` меняет.
Последние формы — только наблюдения официального сервера; эта работа
не добавляет их поддержку в ядро. Без углов сохраняется rotation моба.

Семь неверных форм (NaN,Infinity,~bad,~NaN,неверная координата,недостающий
pitch,лишний аргумент) оставили Pos/Rotation/Motion/OnGround неизменными.
Проверка ядра должна отдельно доказать эти результаты по реальным пакетам;
официальные наблюдения сами по себе не доказывают работу нашего handler.

Повторить официальную пробу в выделенном MC-окне, без параллельной сборки:

```sh
python tools/protocol-bridge/probe_mob_teleport.py \
  --repo "$PWD" --jar /путь/к/проверенному/server.jar \
  --data /путь/к/candidate-json --output /новая/папка --port 26028
```

Сейчас runner содержит все29cases. Для отдельного уточнения можно повторять
`--case pitch270 --case pitch_minus270 --case pitch360 --case pitch_minus360`.
Он проверяет pinned SHA1 JAR и SHA256 JSON, использует собственный Client,
localhost/временный мир/2CPU, сохраняет raw packets, точный SNBT иserver.log.
`--output` должен быть новой папкой. После завершения останавливает только
свой процесс. `data get` используется здесь на официальном сервере;
проверка ядра должна читать сетевые position/rotation/head вместо этой команды.

Сетевая проверка ядра выполнена: **26 случаев PASS**, exit0, 2026-10-20.
Точные position sync, body/head, omitted rotation и все7malformed unchanged
совпали с официальными наблюдениями. Ни одно ожидание не ослаблялось.
Артефакты handoff `verification-mob-teleport775/core-1`; SHA256 результата
`5e0adb6c7db1e299b7ddc7828af63740ac9d46ccd1a74d003f6a7c45f6d72208`.
Saved test binary SHA256
`e1bad7adb14705c48e3340a18afb9fcd9435199d53e93a4840fda9cf227d724c`
из batch2727PASS. После проверки собственный процесс завершён,26026 свободен.
Это сетевая проверка конкретных команд, не графический smoke и не полная
совместимость всех сущностей/команд.

Повторить проверку ядра:

```sh
python tools/protocol-bridge/probe_mob_teleport_core.py \
  --test-binary /путь/к/сохранённому/test-binary \
  --data /путь/к/candidate-json --output /новая/папка
```

Использует существующий ignored `gameplay_probe::serve_java_26_3_probe`
на26026 с клиентом775 и временным marker-миром. Проверяет26 console/player
случаев из fixture; три execute-случая явно вне scope. Успешная команда
обязана дать свежий Position Sync с точными xyz/yaw/pitch и правильный head;
для ошибочной опубликованное состояние должно остаться неизменным.
Data get не вызывается. Внутренние fall/teleports счётчики проверяют Rust
unit tests, не сетевой runner. Повторный запуск — только с проверенной сборкой
и выделением отдельного MC-окна; сам скрипт не запускает Cargo.

Offline replay нового parser на старых записях проверил position/body/head
для28 команд. Для omitted первоначальный recorder не сохранял relative-only
пакет: в записи остаются SNBT позиции и пакеты поворота. Это ограничение
сохранено явно, decoder relative проверен собственным синтетическим пакетом.
Официальный runner теперь сохраняет также `rel_entity_move`; старые записи
не изменялись и новое доказательство для них не выдумывалось.
