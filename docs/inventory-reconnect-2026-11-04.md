# Вещи при переподключении и снимок открытого станка

Работа относится к Java 26.3. Полная строка A06 общего перечня ещё не зачтена.

## Обычный обрыв соединения

Новая отдельная проба проверяет восемь случаев: личный курсор, входные предметы
сетки 2×2, верстака 3×3 и курсор сундука с остатком в сундуке. Каждый случай выполняется
с явным закрытием окна и TCP FIN, затем с открытым окном и TCP RST.
Проверяемые переносы выполняются пакетами обычных щелчков; команды только
готовят площадку. После повторного входа сундук открывается настоящим
взаимодействием с блоком.

Сохраняются 16 авторитетных снимков и входящие пакеты, из которых снимки
восстанавливаются повторно. Предварительный результат крафта исключён из
подсчёта вещей. Сравниваются количество, конкретные слоты и курсор;
номера окна и ревизии не сравниваются. Второй игрок остаётся наблюдателем
во время отключения первого. Стопки на земле читаются из метаданных сущностей
и включаются в общий подсчёт; неизвестный или обрезанный формат отклоняется.
Мир замораживается после загрузки площадки, чтобы снимок не зависел от
движения и подбора предмета. Сравнивается распределение между рюкзаком,
курсором, сундуком и землёй, а не только итоговое количество.

Область ограничена свободным местом в рюкзаке и простыми предметами.
Полный рюкзак, дальнейший подбор выпавших стопок, данные предметов, перезапуск,
станции кроме верстака и Bedrock требуют отдельных сетевых проверок.
Синтетические проверки стенда не заменяют свежий парный запуск.

Первый официальный запуск41889607814 остановился на неверном предположении
стенда: при открытом курсоре и TCP RST оригинал выбросил stone×3 на землю.
Вариант с явным закрытием окна и FIN вернул stone×3 в слот36. Приход
сущности item72 и метаданных Slot stone×3 подтверждён входящими пакетами
наблюдателя. Этот FAILED сохранён; ядро в том прогоне ещё не запускалось.
Проба расширена учётом земных стопок, критерий сохранения количества не ослаблен.

Повтор41890491681 записал12 снимков на каждой стороне. Количество вещей
сохранилось во всех шести случаях. Все три FIN совпали по слотам и земле;
три RST выявили расхождение: оригинал выбрасывает курсор и входы личной
сетки2×2, ядро возвращает их в рюкзак. Сундук сохраняет свой остаток.
Этот результат сохранён как FAILED; полное совпадение не заявляется.
Проверка верстака добавлена отдельно перед изменением cleanup.

## Авария процесса при открытом личном окне

Обычный EOF вызывает возврат содержимого личного окна и сохранение.
Однако прежнее автосохранение копировало только инвентарь: реальные входные
предметы открытого станка находились в отдельном окне и не попадали в файл.
Если процесс завершался аварийно после такого сохранения, эти входы терялись.

Исправление строит отдельный снимок для файла игрока. В нём входы станка,
оплата маяка и две входные ячейки торговли попадают в существующую очередь
возврата. Результат рецепта, содержимое общего сундука, вагонетки, эндер-сундука
и окна плагина туда не копируются. Живые ячейки и открытое окно не меняются.
Сравнение перед автосохранением использует тот же снимок: изменение одного
входного предмета тоже требует записи. Без таких входов используется ссылка
на живой инвентарь, без лишнего копирования.

После восстановления очередь возвращается штатным путём: при полном рюкзаке
вещи остаются в ней до появления места. Обычное закрытие окна заменяет
предыдущий снимок актуальным инвентарём; повторно входы не добавляются.
Формат файла не меняется. Уже потерянные прежними сборками вещи восстановить
из отсутствующих данных нельзя.

Это защита состояния последнего успешно записанного файла игрока.
Общая транзакция между файлом игрока и миром, откат после сбоя записи
и точное совпадение аварийного восстановления с оригиналом не заявляются.

## Проверки

Свежие результаты GitHub будут внесены после завершения прогонов.
Тестовые серверы используют отдельные миры, порты и сетевые пространства.
Рабочие серверы, релизы и Docker этим пакетом не обновляются.
