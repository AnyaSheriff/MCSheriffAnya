# Сохранение произвольного custom_data предметов

Раньше creative-пакет сохранял из `custom_data` только известную служебную
метку нашего TNT. Остальные поля обычного предмета терялись: после приёма
предмет уже не содержал исходный compound. У особого TNT отдельный сетевой
кодек также подменял полные довески его оформлением. Это разбор прежнего
собственного кода; свежего живого сравнения этой ошибки в данном пакете нет.

Изменение `9c52e9d6f148bbcc3a26f495eac24c28a12e9e8c` добавляет хранение
типизированного Java NBT в `Data.custom_data`. Принимается безымянный корневой
compound. Сохраняются все 12 типов: byte, short, int, long, float, double,
byte array, string, list, compound, int array и long array. Числа не проходят
через JSON или SNBT; исходные биты float/double, значения long, типы массивов
и порядок элементов списка сохраняются. Поля каждого compound сортируются
по байтам имени, поэтому порядок полей не меняет равенство и хеш стопки.

## Пути чтения и записи

`src/stackdata/custom_data.rs` проверяет структуру NBT и строки MUTF-8,
сохраняя проверенные байты. В частности, NUL кодируется двумя байтами,
а дополнительные символы — суррогатными парами. Правила строк взяты из
библиотечной спецификации
[Java 25 DataInput: Modified UTF-8](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/io/DataInput.html#modified-utf-8).
Это документация Java API, не исходники Minecraft, другого ядра или
протокольной библиотеки.

Общий кодек компонентов теперь передаёт `custom_data` в обычных слотах,
вложенных предметах шалкера и мешка, а также в поддержанных зарядах арбалета.
Файловая запись довесков получила новую метку 22; прежние номера меток не
меняются. Эти довески участвуют в сохранении игрока и хранилищ, слиянии
стопок и сетевой выдаче предмета на земле.

При выдаче особого TNT его служебная метка объединяется с compound:
компонент 0 записывается один раз, пользовательские поля остаются.
Прежний TNT только с известной меткой сохраняет прежнее внутреннее
представление. Конфликт метки с внутренним видом TNT отвергается проверкой
каталога; добавление метки не должно создавать несохраняемую стопку.

В creative-пути полный пакет и допустимость предмета проверяются до
изменения инвентаря. Читатели компонентов мешка, контейнера и зарядов
сначала разбирают временное значение: повреждение или лишний хвост не
заменяют переданные довески.

## Собственные ограничения

NBT-компонент ограничен 65 535 байтами, глубиной вложенности 32 и бюджетом
65 536 значений. Вся файловая запись довесков также должна помещаться
в 65 535 байт, поэтому для `custom_data` остаётся меньше места при наличии
других полей. Длины и произведения размеров массивов проверяются до чтения.
Это ограничения нашего формата и защиты читателя, не измеренные лимиты игры.

Повторяющиеся имена внутри compound и повтор компонента в добавлениях либо
одновременно в добавлениях и удалениях отвергаются. Согласованность такого
отказа с оригиналом ещё требует отдельной пробы `[проверить]`.

Полного типизированного SNBT в командах пока нет: `custom_data=...`
отвергается явной ошибкой, в том числе во вложенных предметах. Перенос
пользовательских данных Bedrock этим изменением не реализован. Не заявляется
сохранение всех остальных, пока неподдержанных компонентов предмета.

Равенство float/double здесь сравнивает исходные биты, включая знаковый ноль
и разные представления NaN. Это сохраняет данные, но совпадение правил
слияния таких редких значений с оригиналом пока не измерено `[проверить]`.
Данный пакет не подтверждает полную совместимость предметов или Minecraft 26.3.

## Проверки и их границы

Добавлены проверки полного пути creative → файл игрока/хранилище → выброс →
сетевой пакет для профилей 26.1.2 и 26.3. Отдельные проверки покрывают
вложенные предметы, дополнительные поля TNT без второго компонента 0,
слияние стопок с сохранением типов и чтение прежних файлов без `custom_data`.

Отрицательные случаи включают обрезание пакетов, лишние байты, повтор
компонента 0 сверху и во вложенных предметах, повтор ключа compound,
неверные и оборванные MUTF-8 строки, точные границы глубины и размера.
Проверяется неизменность прежнего инвентаря или довесков при отказе.

[Полный CI 41118157596](https://github.com/AnyaSheriff/MCSheriffAnya/actions/runs/41118157596)
прошёл для `39e27cff7804c3aadcb0c9167e0b78e8d1ce2903`. Все 11 новых проверок
`custom_data` и 6 проверок командной экипировки прошли в обоих режимах Rust.
Всего 3539 успешных проверок workspace и 3170 без default features (каждый итог
включает один дополнительный filtered smoke); 116 и 100 соответственно
помечены ignored. Строгий Clippy без предупреждений, WASM-примеры, release build,
37 Node и 14 Python проверок также прошли. Два проверяющих независимо сверили
12 контрольных сумм артефакта и наличие новых тестов в обоих журналах.

Бинарник: 47 940 784 байта, SHA256
`409e7c8f66c5c32bde8ab0050be86990d4fb627234302dbf4ef0b8040bc9cabd`.
Для игровых сравнений оба runtime pin закреплены на этой сборке.

Предыдущие попытки сохранены отдельно: 41112951152 остановилась на ошибках

Локальные Cargo и Minecraft для этого пакета не запускались. Свежих живых
проверок `custom_data` на оригинале и нашем сервере в этом пакете пока нет;
