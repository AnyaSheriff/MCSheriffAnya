# FourLegacy on main (0.2.9)

- **Not yet translated or loaded:** move/jump/interact, armor, bed, chat and respawn delivery, permission inheritance and more world reads are now supported. The unchanged JAR still fails the remaining API audit. No FourLegacy clan/race/ability bot proof is claimed.
- Audit: initial 2,676 diagnostics / 727 distinct reasons; previous checkpoint 2,333 / 673; previous **1,383 / 464**; previous **1,057 / 371**; previous **889 / 316**; current **574 / 220**. Exact signatures and call sites: [JSON](../tmp/fourlegacy/missing-current.json).
- Reproduce: `python3 tools/plugin-translator/translate.py tmp/fourlegacy/FourLegacy-0.1.1.jar --check-only --report tmp/fourlegacy/missing-current.json`.
- Continued port: **889 / 316 → 850 / 306 → 799 / 289 → 710 / 256 → 641 / 239 → 623 / 231 → 619 / 229 → 584 / 223 → 574 / 220** (diagnostics / reasons). Each group was audited against the unchanged FourLegacy JAR; no missing event handler is admitted merely by adding a class.
- Added: all 46 base potion variants from this core's existing effect table, `Registry.POTION`, effect categories and copied `PotionMeta`. Base-potion changes cross the item bridge into native potion contents and survive item serialization; existing custom effects remain preserved by native tokens.
- Added: live player fire/environment/pose/eye/active-item/effect reads, queued damage and experience; snapshots are collected only with plugins active. Generic entity velocity reads/writes cover players, mobs, dropped items and the core's thrown projectiles. Player writes send a real motion packet. Dropped items support creation, location, same-dimension teleport, validated item replacement and removal. Removing a player refuses in Russian and directs the plugin to `kickPlayer`.
- Added: block light, passability/liquid and age snapshots, full block-state text/restoration (force/physics options), loaded-chunk and highest-block queries, random tick speed and real random block ticks. Natural breaking uses native drops and the core's paired-block/neighbor logic. Sound and particle catalogs currently expose the six requested sounds and heart/happy-villager particles, with bounded arguments.
- Added: cancellable held-slot, hand-swap and consume delivery before selection/swapping/consumption; consume cancellation preserves the item and suppresses food/potion effects. GUI drag handlers now receive actual selected raw slots and the pre-transaction cursor. `BlockPlaceEvent` supports the owner's synthetic-event constructor and build decision. Source-aware damage exports remain optional for old components: player direct attackers receive `EntityDamageByEntityEvent`; mobs/projectiles still require their own wrappers and remain an explicit limitation.
- Refused: Paper `setFlyingFallDamage` stays a translation failure with «Правила Paper для урона при полёте не поддерживаются: setFlyingFallDamage; требуется явная настройка физики ядра». Flight/bed rule overrides are not replaced by successful empty methods. This refusal still blocks the unchanged FourLegacy JAR, alongside the other audited missing APIs.
- New public signature references: [potions](https://jd.papermc.io/paper/1.21.8/org/bukkit/potion/PotionType.html), [categories](https://jd.papermc.io/paper/26.1.2/org/bukkit/potion/PotionEffectTypeCategory.html), [potion meta](https://jd.papermc.io/paper/26.1.2/org/bukkit/inventory/meta/PotionMeta.html), [entity](https://jd.papermc.io/paper/26.1.2/org/bukkit/entity/Entity.html), [item](https://jd.papermc.io/paper/26.1.2/org/bukkit/entity/Item.html), [block](https://jd.papermc.io/paper/26.1.2/org/bukkit/block/Block.html), [world](https://jd.papermc.io/paper/26.1.2/org/bukkit/World.html), [held](https://jd.papermc.io/paper/26.1.2/org/bukkit/event/player/PlayerItemHeldEvent.html), [consume](https://jd.papermc.io/paper/26.1.2/org/bukkit/event/player/PlayerItemConsumeEvent.html), [damage source](https://jd.papermc.io/paper/26.1.2/org/bukkit/event/entity/EntityDamageByEntityEvent.html). API source and API JARs were not read.
- Added: world environments, per-world player lists, native block-type reads, relative blocks and the core’s actual height range (-64..320). Material/key/decoration names use ASCII case conversion; Unicode chat text is preserved. Single-slot and armor reads decode only requested items, and armor polling starts only for components with armor handlers. This keeps cold joins/reloads under the original fuel limit.
- Added: C/WASI float/double parsing and round-trip formatting, replacing faulty TeaVM conversion (including subnormals); bounded ASCII decimal/hex input (4096 characters), Java suffixes, signed zero, infinity/NaN and rejected malformed input. Compiler arithmetic uses wrapping integer semantics. The port preserves GC roots and exception call-site metadata.
- Added: packet-backed move/jump and interact events before physics/item use, with cancellation and validated movement destinations; respawn destinations (including dimension) and bed/anchor flags. The optional `player-events` export leaves older components compatible. Armor-change notifications compare published inventory snapshots once per tick; multiple changes within one tick are coalesced.
- Added: Paper chat handlers and per-viewer Adventure renderers. Custom rendering owns final delivery in the Bukkit component (and suppresses the default chat); later independent components do not receive an already rendered/cancelled message. Legacy handlers run first. Threads are still serialized by the host.
- Added: validated plugin.yml permission defaults (`true/false/op/not op`), explicit child edges, cycle protection, actual operator levels, command permission checks and aliases. A `default: false` bypass remains false for operators unless inherited explicitly. Asterisks are literal names with explicit children. Declarations are component-local; cross-plugin permission graphs, attachments and admin grants are not yet exposed.
- Added: read-only bed decisions from the core (reach, obstruction, dimension, nearby monsters and daylight), cancellable bed entry and persisted personal respawn points. `setUseBed(ALLOW)` refuses in Russian: «Принудительный сон в обход правил мира не поддерживается; используйте DEFAULT или DENY». Arbitrary Paper bed-rule overrides and flying-fall-damage rules remain unsupported; no successful empty implementation is substituted. Interaction currently supports cancellation of the whole action; independent block/item result setters remain rejected by the audit.
- API signatures were checked only against public Javadocs: [move](https://jd.papermc.io/paper/1.21.8/org/bukkit/event/player/PlayerMoveEvent.html), [interact](https://jd.papermc.io/paper/1.21.8/org/bukkit/event/player/PlayerInteractEvent.html), [jump](https://jd.papermc.io/paper/1.21.8/com/destroystokyo/paper/event/player/PlayerJumpEvent.html), [armor](https://jd.papermc.io/paper/1.21.8/com/destroystokyo/paper/event/player/PlayerArmorChangeEvent.html), [chat](https://jd.papermc.io/paper/1.21.8/io/papermc/paper/chat/ChatRenderer.html), [respawn](https://jd.papermc.io/paper/1.21.8/org/bukkit/event/player/PlayerRespawnEvent.html), [bed](https://jd.papermc.io/paper/26.1.2/io/papermc/paper/block/bed/BedEnterAction.html), [permission defaults](https://jd.papermc.io/paper/1.21.8/org/bukkit/permissions/PermissionDefault.html), [world](https://jd.papermc.io/paper/1.21.8/org/bukkit/World.html) and [relative blocks](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/block/Block.html).
- Added: real custom chest windows (9..54 slots), holders/views, cancellable open/click/drag and close events. Host transactions handle normal/right/Shift/number/offhand/double clicks, creative cloning, drag distribution, cursor return and unload cleanup. Java native views expose snapshots; writes to their top inventory are explicitly refused in Russian. Events currently cover the component's custom GUI only.
- Added: main scoreboard teams, Adventure prefixes/suffixes/colors and membership reach Java clients, including join snapshots and unload cleanup. Added `getPlayerExact`, current tick, vector/location distance/direction and nearby-player bounding boxes. Java objectives/scores and personal boards remain missing.
- Added: `newSingleThreadExecutor` / `newFixedThreadPool(1)` use one bounded FIFO per component, serviced by the host between ticks. `execute/submit`, futures, cancellation, shutdown/close are supported. Unused lambda thread factories are removed, including captured factories; arbitrary real threads remain refused in Russian.
- Added: confined File/Path/Files, bundled resources, nested YAML lists/maps/scalars and saving; all 13 embedded YAML resources match safe SnakeYAML. Tags/anchors/block strings remain unsupported. Record equals/hashCode/toString are lowered without reflection.
- Added: player inventory snapshots, stacking/removal, armor/offhand; copied item meta, names/lore, enchantments, damage/custom durability, typed PDC persisted with items. Entity/player PDC is coalesced and saved by UUID in the component's data folder, with an unload flush.
- Added: player attribute bases/modifiers with immediate projected reads and host queue mutations. Modifier keys belong to the plugin. Attributes are runtime state; some attributes, including scale, are not fully reflected in server physics. Native item extras use bounded host-issued transfer tokens.
- Added: HTTPS host declarations AND explicit admin grants, GET/POST only, bounded requests/replies/time/concurrency, pinned public DNS, no credentials/redirects/system proxies. Startup logs show each plugin's allowed hosts. [Configuration and limits](../tools/plugin-translator/README.md#разрешения-https-и-настройки-мира). A real external TLS round trip is not part of the proof.
- Added: core `monster-spawn-multiplier=1` and `ore-retention-percent=100`; defaults preserve previous behavior. Ore thinning affects newly generated chunks only. These settings do not automatically mirror FourLegacy's config.
- Missing: remaining event classes (including mob/projectile-aware damage, mob death, drop, native-container inventory events), scoreboard objectives and remaining entity/world/spawn/potion APIs; the audit is authoritative. Paper bed-rule overrides/flight APIs remain refused by the Russian signature audit; no successful empty implementation is substituted. PlaceholderAPI remains absent; its optional type cannot be instantiated/registered.
- Existing limits: combat notifications target players; player direct attackers are mapped, while mob/projectile source mapping remains incomplete. Damage cancellation does not undo armor wear computed earlier; death is read-only. Inventory/health reads use Java connection snapshots.
