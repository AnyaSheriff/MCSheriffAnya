# Android ARM64 / Termux

Для обычного Termux нужен отдельный файл `mcsheriffanya-android-arm64`.
Он собран для `aarch64-linux-android`, Android API 24 (Android 7.0) и новее.
Обычная Linux ARM64 GNU-сборка использует другую системную библиотеку и
для прямого запуска в Termux не подходит.

Сборка сохраняет обычные возможности сервера, включая WebAssembly-плагины.
Это не APK: устанавливать его как Android-приложение не нужно.
Для HTTPS в Android-файл встроены корневые сертификаты Mozilla: это позволяет
проверять сертификаты без JavaVM, которой нет у самостоятельного процесса Termux.
Проверки подлинности сертификата, имени сервера и срока действия сохраняются.
Пользовательские корни Android при этом не используются; обновление встроенных
корней требует новой сборки.

## Получение и запуск

В GitHub Actions открыть **Android ARM64 build**, выбрать успешный запуск
и скачать его артефакт. Внутри есть отдельный исполняемый файл, архив
с документацией и лицензией, `SHA256SUMS` и сведения о сборке.
Проверить суммы командой `sha256sum -c SHA256SUMS` рядом с обоими файлами.

Перенести исполняемый файл в отдельную папку внутри домашней папки Termux.
Не запускать сервер из общей памяти `/sdcard`: там другие права и ограничения.
Например, после копирования файла в `~/mcsa-android`:

```sh
cd ~/mcsa-android
chmod +x mcsheriffanya-android-arm64
./mcsheriffanya-android-arm64
```

Сервер создаёт настройки и мир в текущей папке. Для первого испытания
использовать новую пустую папку, без единственного экземпляра старого мира.
Далее проверить вход клиента, сохранение и штатную остановку сервера,
повторный запуск с тем же миром, а также нужные плагины.

## Что проверяет сборка

GitHub собирает файл через установленный Android NDK, выбирая
`ANDROID_NDK_LATEST_HOME`, затем `ANDROID_NDK_HOME` при отсутствии первого.
Точная версия NDK, API24, версия Rust и исходный коммит записаны в квитанции.
Сборка проверяет ARM64 ELF64 PIE, загрузчик `/system/bin/linker64`, системные
библиотеки Android и отсутствие зависимостей glibc. Журнал сборки сохраняется.

Отдельная задача запускает небольшой HTTPS-тест в эмуляторе Android API35 x86_64
как самостоятельный процесс через adb, без JNI. Она проверяет создание того же
HTTP-клиента, доступ к доверенному HTTPS-сайту и отказ для самоподписанного
сертификата местного стенда. Тест собирается без плагинов; основной ARM64-сервер
по-прежнему собирается с плагинами. Результат теста виден отдельно в Actions.

Эти проверки не запускают ARM64-сервер на телефоне и не подтверждают совместимость
со всеми устройствами. До ручного испытания запуск Android, работа плагинов
и длительная работа сервера остаются непроверенными. Android может ограничивать
фоновую работу и расход памяти; производительность зависит от устройства.

Привязка потоков к ядрам и безопасное обновление старых форматов мира сейчас
включены только в Linux-сборке. Android может создавать новый мир и читать
поддержанный текущий формат; мир, требующий такого обновления, будет отклонён.
Автоматически обходить эту проверку или переносить единственную копию мира нельзя.

Workflow запускается на ветках `wip/arm64-*`, `wip/android-*` и вручную. Он не создаёт релиз,
теги или публикации. Для ручного запуска после слияния выбрать этот workflow
во вкладке Actions.
