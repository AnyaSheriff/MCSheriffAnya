# Экспериментальные расчёты мобов и отдельное отключение измерений

Настройки находятся в `config/mcsa.properties`, применяются после перезапуска.

```properties
experimental-parallel-mobs=false
mob-tick-threads=0
enable-nether=true
enable-end=true
```

`experimental-parallel-mobs=true` разрешает дополнительных исполнителей для
независимого поиска угроз жителями и целей ламами, белыми медведями и агрессивными
пандами **внутри одного измерения**, а также передачи тревоги пчёлами и
дельфинами. По умолчанию режим выключен.

Тревога рассчитывается по снимку в прежней точке такта, после предшествующих
ударов и взаимодействий. Основной поток применяет результаты в старом порядке:
последний подходящий источник побеждает, включая очистку прежней цели. Урон,
эффекты и остальные взаимодействия в эту параллельную работу не входят.

До первого измеренного такта **строго больше 50 мс** расчёты последовательные.
После превышения со следующего такта доступен второй исполнитель, если замеренная
пригодная работа мобов заняла хотя бы 1 мс. Нужна хотя бы одна группа от 64 целей
и 16384 предполагаемых сравнений; множество маленьких групп не заменяет большую.
При параллельном расчёте учитываем также сумму длительностей отдельных заданий,
чтобы выигрыш по времени сам по себе не отключал помощников на следующем такте.
Дальше каждые20подряд перегруженных тактов добавляется один исполнитель.
Бюджет общий с `parallel-dimension-ticks`: обе фазы идут по очереди,
пределы не складываются; каждая сохраняет свой выключатель и ограничение.
При включённой блочной фазе полезная работа нескольких измерений тоже может
расширить общий бюджет. Это не переводит движение мобов в другие потоки.
`mob-tick-threads` ограничивает общее число вместе с потоком такта: 1–8;
0 означает автоматически, максимум восемь и не больше доступных логических CPU.

После200тактов меньше40мс либо без достаточной полезной работы бюджет
уменьшается на одного. При40–50мс и достаточной работе уже выделенный
бюджет сохраняется, чтобы не переключаться каждый такт. Заморозка,
пауза пустого сервера и активные плагины возвращают последовательный режим.
Ожидающие потоки спят; при выключенной функции они не создаются.

Рабочие задания получают только снимки координат и признаков. Порядок исходных
списков и выбора цели сохраняется. Применение результатов, движение, общая
случайность, урон, появление мобов и изменение мира остаются последовательными.
Это первый участок работы с мобами, **не параллельное выполнение всего ИИ**.
Быстрый поиск целей не гарантирует ускорения всего такта, если его задерживает
другая работа. Измерения производительности нужно оценивать на своей нагрузке.

`enable-nether=false` и `enable-end=false` — **отдельные ручные настройки**.
Они никак не зависят от длительности такта: сервер сам измерения не отключает.
Обычный мир работает всегда. Отключённые миры не открываются с диска, не получают
тики, не загружают чанки, недоступны порталам, переходам и командам. Их папки
сохраняются. Игрок, вышедший в таком мире, при следующем входе попадает в обычный
мир; вещи и сохранённая личная точка возрождения не удаляются. При включении
измерения обратно используются его прежние файлы.

Параллельное исполнение целых редстоун-механизмов пока не реализовано.
План границ и проверок: [отдельный документ](experimental-redstone-mechanisms.md).
Настройка `parallel-dimension-ticks` относится только к блочной части разных
измерений. Её адаптивный порог теперь тоже строго>50мс общего такта; полный
тик измерения с сущностями и командами по-прежнему не распараллелен.
